# 精简拆解：一个问题，三条可带走的技法

> **用途**：分析模式的默认交付。用户问“这段为什么好看、我能学什么”时，用一页答清楚，不填完整拆解卡。
> **何时改用完整拆解卡**（`拆解卡模板.md`）：用户要完整拆解、要入库或更新库卡、要做多本比较，或明确要五层逐项拆。
> **篇幅参考**：一千五到两千五百字。条数按实际发现，可以是两条，不凑三条。

## 写法约定

- **引号里只放逐字原文**，并附章号或行号。转述、概括、自己起的术语不加引号；回目、篇名用书名号。交付前跑 `python3 -B scripts/quote_check.py <原文> <本稿>`，未逐字命中的条目逐条改回原文或去掉引号。
- **判断直接写**。只在一句话可能被误读成原文事实时，才标【推断】；不逐句贴【事实】【推断】。
- **范围一句话说清**：读了哪一段、没读哪些，不展开成表格。

## 模板

```markdown
# 《书名》某段：一句话说清这段好看在哪

范围：读了【章/行范围】；未读【其余部分】。版本：【来源或文件】。

## 这段怎么组织的

【三到五句：从哪里起压、怎样一步步加码、在哪里兑现、兑现后留了什么后果。关键处附章号/行号，必要时逐字短引。】

## 技法 1：【技法名，一句话】

- 原文怎么做：【具体动作与位置；逐字短引放引号里并附行号】
- 为什么起效：【读者体验上的原因；这是分析判断】
- 带到你的书里：① 【第一步】 ② 【第二步】 ③ 【第三步】
- 必须重造：【换题材时要重新设计的欲望、能力边界、对手筹码或代价】
- 什么时候失效：【一句话】

## 技法 2：……

## 技法 3：……（有则写）

## 迁移包（交规划或写作时附上，缺项写无）

目标题材与阅读痛点；可迁移的体验；三步做法；必须重造的部分；主动舍弃的原著专有事件链或降智桥段；失效边界。
```

## 自检

- 每条技法都能在原文里指到位置吗？引号里的字是否全部逐字命中？
- “为什么起效”有没有写成读者已经这样反应的事实？没有读者数据就写成分析。
- 三步做法离开原著人物和道具，换一个题材还能执行吗？
