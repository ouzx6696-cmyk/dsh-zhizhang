# 三阶段与写作任务交接

> 共同的主责、状态和权限语义见 `references/handoff_contract.md`；本篇只补规划进写作、正文回规划与委派细节。授权与正文验收见 `references/writing.md`。角色是一组职责，不要求每章创建多个代理。

## 一、三个阶段，不是强制三连跑

- `inspiration-forge-library`：指定原文与范围 → 有出处、阅读范围、解释与迁移条件的写法知识；分析不强制入库，仅在授权后写库，不写作者规划。
- `inspiration-forge`：相关机制与作者材料 → 根基、必要的阶段/幕纲、可开写章纲；只读库，写作品根，不写正文。
- `novel-writer`：现行章纲与本书写法 → 草稿 → 编辑回读 → 用户确认或已明确授权的归档；从实际定稿校准接续。

用户有章纲可以直接写，有作者材料可以直接规划，只有拆解请求就交知识。上一阶段完成不自动启动下一阶段，不自动授权归档或投稿。未安装所需技能时如实报告，仅停止依赖它的工作；规划交给实际可用的 `inspiration-forge`。

## 二、规划进入同一个作品根

路径相对用户指定的作品根，不相对技能根或库根。技能资源路径相对当前技能根。

| 现行材料 | 下一步怎样用 |
|---|---|
| `state/story_foundation.md` | 主代理读主线、人物、规则，区分作者锁定、定稿事实、候选与作废；已有有效内容保留，不按写作模板重建 |
| `workspace/volumes/V01.md` | 多卷导航，单卷可无 |
| `workspace/acts/A01.md` | 当前单元的输入、具体推进与输出；单章任务可把必要依据放章纲头注，不强造幕文件 |
| `workspace/outlines/C001.md` | 直接使用四块正文与头注，不再抄一份写作章纲 |
| `state/current_state.md` | 规划进度与正文快照分区；规划完成不等于正文发生 |
| 按需细目 | 复杂幕拆分在 `workspace/plans/`，卷级推演在 `workspace/rehearsals/`，跨幕导航在 `workspace/summaries/`，外部润色候选在 `workspace/polished/`。只读与本章有关的链接；关键依据须进入章纲。已有作品若用 `planning/`，沿用，不批量改名 |

接收时先读实际现行文件。四个正文标题写作 `## 1. 剧情梗概`、`## 2. 核心冲突与看点`、`## 3. 情节推进节点`、`## 4. 章末落点`。作者自有格式内容充分时直接使用，只在确有冲突的范围适配，不为机械检查改故事。

头注有视角、目标篇幅、锁定事实、人物知识边界；承接与“人物此刻”（想办成什么、顾虑什么、手边有什么）按需要补充。人物动机已在节点写清就不强抄三遍。不增第五块正文；关键物件写进有关节点或头注。节点按真实经历顺序，起承转合只作参考。

写作前才补 `state/writing_style.md`、`state/editor_agent.md`、`state/constraints.md` 的必要内容；不要求规划阶段先填这三份。风格来自用户取舍、本书正文或可追溯参考；三者都没有时，可从番茄长篇默认取向起步并在交付中说明，作者确认后才算本书讲法。`constraints.md` 是编辑用的硬边界入口，可链接根基的现行规则与定稿出处；同条规则只保留一个完整权威版本。章纲头注是本章必要条件的局部投影，不是另一份全书约束库。

## 三、主代理派写前做什么

读本章章纲、相关根基与硬边界、当前正文入口，并把本章需要遵守的条件和知识边界补到章纲。已有定稿与章纲或作者锁定冲突时停依赖它的写作；不要让写手先写、编辑再发现必然违规。

正文快照可能落后。主代理核清快照截至章号，读取其后与本章有关的定稿范围，在派单中给出有出处的必要增量；至少让写手读上一章定稿全文。找不到早先证据时定点补查，不默认全书重读，也不以“只许看上一章”屏蔽真实冲突。

## 四、主代理 → 写手

通常给五类材料：本章章纲、上一章定稿全文（首章无；连续草稿则给所依赖的前稿全文并标候选）、当前幕纲或最小单元依据、当前状态与已核必要增量、本书写作风格。缺失项先判断是否真正影响本章，不能把“全文五份”当固定数量门禁。

另外给清：本轮章号与范围、是否单元末、已有草稿路径、唯一可写目标。写手不承担规划选择、定稿或归档，不读整份编辑方法；全书硬约束由主代理抽取本章必要条件，编辑持有完整入口。

子代理没有父代理上下文。派单必须给实际技能根/作品根、材料路径、授权范围、输出与停点。子代理不会自动继承写作方法；给出当前技能入口或本任务必要方法路径，不仅说“按技能写”。

```text
你只写 CXXX，作品根：<绝对路径>，技能根：<绝对路径>。
读本章章纲、上一章定稿全文（首章无；连续草稿读已声明候选前稿全文）、相关幕纲或最小依据、状态与有出处增量、本书风格。
方法入口：<当前技能根>/references/writing.md、rhythm.md。
关键因果、知识边界与章末落点不改；具体措辞、微动作、现场对白由你完成。
落稿后自检两件事：删掉卖点改变局面的那一拍，结果会不会变；读者读完本章多得到了什么。谨慎只管事实，不替代事件。
已有草稿：<路径或无>，相容时接着改，不另起替代稿。
只写 <作品根>/workspace/drafts/CXXX.md，不归档、不改规划或状态。
完成回报草稿路径、实际落点；缺关键依据或结构冲突时报告具体缺项，等待主代理处理。
```

安静、单场或完整收束不是失败。篇幅与内容明显不适配就回报具体影响；写手不删关键节点留到下一章，也不为凑场数发明剧情。

## 五、主代理 → 编辑 → 主代理

编辑拿草稿全文、本章章纲、硬边界入口、本书编辑配置与实际技能根的 `references/editor_method.md`、本书风格、上一章定稿全文与必要的早先事实出处。涉及日期、天数或金额时，可先用 `scripts/ledger_check.py` 列出幕纲、章纲与前后章的数字对照。返工带上轮问题与实际修改，不扩大成全书审计。

输出：通过/未通过/结构性冲突；阻塞项给位置、影响与最小修改方向，可选表达意见与硬伤分开；说明是否完整回读修改后的正文，并绑定实际改后版本；草稿变动使旧审读结论失效。编辑只改授权草稿，不能改章纲关键结果、作者锁定或已定稿事实来制造通过。

问题解决后主代理按用户实际授权交稿或归档。反复修改仍有硬伤时保留草稿并报告断点，不以“两轮已到”带硬伤放入定稿。可选小瑕疵可以保留，不必追求无尽打磨。

## 六、归档与接续

归档前独立核真实授权与当前已审版本，核目标不存在；可用 `scripts/archive_draft.py` 绑定已审 hash 并独占创建。将同一已审字节复制为 `workspace/chapters/CXXX.md`，保留草稿，不顺手再改正文。目标已存在则不覆盖；核清它是否是本轮授权范围的现行定稿，再决定跳过或停止，不能只见同名文件就认定该章已完成。授权修订已有定稿另走 `references/revision.md`，本步骤不覆盖。

章与章有事实依赖时串行。主代理给下一章传实际落点、新增/失去、人物获知与活跃未结，并给定稿出处；不只在对话中报一句就假定独立写手已收到。

批次/单元末，或跨会话确有接续需要时，更新 `current_state.md` 的正文快照与接续入口，保留规划进度和待决。只有正文支持的事实才进快照；未来纲的状态按实际分别标规划完成、草稿或已定稿。无需每章重写五份状态。

## 七、正文回到规划，而不是自动回到知识库

结果偏离未来规划：先判断是表达偏差、草稿事件变化还是已定稿的新事实。未确认草稿可供条件推演，但不是事实；草稿改变后重看依赖它的后续草稿和未来章纲。

已定稿事实明确且只是快照落后，主代理修派生快照。未来路径需要重排时，把定稿点、相关现行纲、作者锁定、断点与所需范围交给 `inspiration-forge`；它只修受影响的未来规划，完成后再回写作。改变锁定或定稿须请作者决定。

本书自检、生成草稿和单次编辑通过不自动成为已发表作品的写法知识或成功案例；没有新拆解授权不写公共库。确需从指定正文提炼机制时，再按拆解技能声明来源、范围与证据，不补市场效果。
