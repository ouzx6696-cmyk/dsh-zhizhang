# 结构：方向、卷纲、幕纲与章纲

> 规划、章纲卡住或正文发现因果断裂时查阅。先解决故事方向，再把本章要发生的事写具体；不要把提纲变成正文或检查表。
>
> 本篇是**通用方法**，任何一本书都适用。长线商业连载特有的结构方法在 `references/serial_orientation.md`，**启用条件以那篇为准**，此处不复述；不启用时不必读。

## 一、方向从哪里来

下一章至少要能回答两件事：这一幕在解决什么，本章为什么接在这里。依据通常来自：

- `state/story_foundation.md` 的主线、承诺、人物和规则；
- `state/constraints.md` 的命名与能力边界；
- `state/current_state.md` 与最近定稿正文中的当前处境；
- 用户这一次明确想推进、想体验或不想改变的内容。

这些依据合起来形成幕内问题，落进幕纲。没有收敛的全书路线、关键因果或后续重排，交给 `inspiration-forge`，不在普通章纲里硬补。

一个幕可以很短，也可以跨很多章。只在多线并进、规则复杂或确实需要中途拆分时建立 `workspace/plans/` 下的计划文件（模板见 `assets/templates/plan.md`）；幕纲和章纲才是日常主线。未来规划是工作依据，不是已经发生的事实。

## 二、卷纲：多卷作品才需要

普通单卷、短篇和暂不按卷组织的书可以省略卷纲。

需要时，卷纲只回答：本卷在全书中的位置、本卷承诺和核心问题、主要冲突与重要变化、幕级结构，以及卷末如何进入下一卷。卷纲是导航，不复写所有幕纲，不逐章排期，也不另存一套事实。远端卷可以粗写，当前卷写实。

模板见 `assets/templates/volume_outline.md`；高风险节点确有需要时，用 `assets/templates/volume_rehearsal.md` 接收 `inspiration-forge` 的推演结论。

检查卷与卷之间是否接得上：下一卷应由上一卷的结果、持续的目标或认知合理承接，人物的新行动能从当时的处境、资源、关系和认知推出。**接不上时补承接依据，不给人物凭空换目标。**

## 三、幕纲：安排因果，不预写正文

幕纲写清：

- 输入状态和本幕问题；
- 主角或主要人物准备怎样应对；
- 输出状态和幕末闭合条件；
- 实际出现的阻力、变化和幕级落点；没有转折就不补；
- 章与章之间的因果接口，以及必须遵守的事实和承诺。

章节因果链是对未来的假设，写到正文后可以改。上一章的结果最好成为下一章的压力来源，但**不是每幕都要升级危机**；关系、生活和认知的变化也可以形成下一步。

幕纲不代替章纲。它只说明一章怎样接下一章，不替每章预填具体对白和过程。模板见 `assets/templates/act_outline.md`。

## 四、章纲：把功能变成事情

四块统一用数字标题：

- `## 1. 剧情梗概`：一两句话写核心事件、主角意图和主线推进。
- `## 2. 核心冲突与看点`：这一章要面对什么。可以是阻拦和代价，也可以是关系、探索或认知；怎样办成或改变了什么。
- `## 3. 情节推进节点`：按**实际经历顺序**写具体事件（起承转合只是可选参考，不强求四拍）。关键证据怎样取得，选择为什么形成，重要谈话、回忆、操作和体验要有实际材料。
- `## 4. 章末落点`：本章最终抵达的结果或体验，以及下一章的真实承接。

视角、目标篇幅、锁定事实、人物知识边界、**人物此刻**和本章为什么接在这里，写在头注（人物此刻也可直接写进节点）。**不要把这些元信息混进梗概**，也不要把"试探""成长""深入交谈"当成事件。

### 让抽象任务变成剧情

从人物此刻的目的与顾虑、现实条件、信息来源、关系回应和未兑现的后果取材。

遇到"交涉后同意""努力后成功"这类跳步，写清第一步怎么做、对方怎样回应、回应怎样改变下一步。**办法确实可行时可以顺利完成，不要为了显得有戏硬造失败。**

发现类场景要写清人物要回答的问题、接触到什么材料、怎样理解、哪些内容仍待核实。证据范围不同，人物说法不能直接当事实。

安静章可以把重新熟悉、陪伴、理解生活或关系移动作为主要内容。**章节推进不只等于打败对手、揭开谜底或制造悬念。**

### 章纲够不够

判据：**写手不应再发明关键因果、关键证据、关键选择或撑起主要篇幅的经历**；正常的措辞、动作和现场细节仍由正文完成。**这一章的人和事不能和别的章互换**——能互换就是模板兜底，要重写。颗粒度参照 `assets/examples/fanqie_outline_example.md`（可选，非门禁）。

前一章的章末变化应能成为本章的起点或动机。若事情本身太薄，调整章节边界或承认篇幅目标不适合，**不要求正文凭空加戏**。

## 五、前台与后台

只问：读者亲历这段材料后，是否会改变理解或感受？

会，就是前台；只是告诉读者事情已经在别处办完了，就是后台。常规手续、成串清单和逐笔数字可以略写，但谈价、核账或专业操作本身若是冲突对象，就必须保留关键过程。

后台提醒写在头注或节点后，**不要把"可略过"写进剧情段让正文照抄**。撤掉的是账目播报，不是人物正在争、做或承担的事情。

## 六、写后逆向校准

**批次或单元末，以及跨会话接续前，连读本批实际涉及的章节。** 单章都合格、连起来读垮掉，是长线最常见也最难救的问题。不要求每一幕的最后一章归档后都做一次。

**因果**

- 每章是否由上一章的结果自然开始；
- 动机断了，核草稿表达或未来承接；只补已授权范围，不倒改定稿补前置；
- 规则被绕过，核现行规则与正文出处，修偏差或报告锁定冲突，不临时补限制救场；
- 幕纲与正文连续偏离，重排剩余安排，不硬写完旧计划。

**人物**

- 人物的欲望、知识和代价是否跨章一致，有没有漂；
- 配角是不是只在主角需要消息时才出现；
- 人物关系是否真的发生了变化，还是每章都停在原地。

**节奏**

- 是不是连续多章用同一种冲突模式；
- 是不是每章都在刻意升级，一章比一章紧；
- 安静段落有没有被当成无效章节。

**表达**

- 风格有没有漂移；
- 对白是不是渐渐变成说明书；
- 有没有过度修剪掉人物声音。

**校准只改受影响的未来规划，不擅自改已定稿正文。** 关键路线需要重排时交 `inspiration-forge`。规则已被正文使用或作者锁定时，不能自行补限制救纲，先报告具体冲突。
`current_state.md` 只更新受影响的规划进度、定稿快照与待决接续，保留其他分区，不顺手整份重写；见 `references/continuity.md`。

## 七、接收外部规划

`inspiration-forge` 交来的成果落到**同一个作品根**的现行材料上，不重新复制一份规划：

- 主线、人物、规则 → `state/story_foundation.md`
- 命名、能力边界、已定稿事实、作废项、数字口径 → `state/constraints.md` 硬边界入口；完整规则保留在现行根基等权威来源，用链接引用，不整份拆抄
- 多卷安排 → `workspace/volumes/V01.md`
- 幕级安排 → `workspace/acts/A01.md`
- 近端章纲 → `workspace/outlines/C001.md` 等
- 卷级推演结论 → `workspace/rehearsals/V01.md`，仍是规划，不是正文事实

落位时**分开作者锁定、未来安排和已经发生的定稿叙事**。外部章纲不因为文件存在就自动获准写作。规划采纳后，本项目在同一个作品根维护一份现行版本（foundation / acts / outlines / current_state），不与旧交接材料并列维护；**有冲突或需要时再回读**，不只读一次就当定论。
