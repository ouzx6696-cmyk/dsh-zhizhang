# 装填工作流：从交付目标到可开写规划

每步都有所需输入、制作动作和下一步用途，不是逐层审批。推导依据见 `方法论.md`，字段见所需模板。任务清楚就执行，只有实质缺项、方向冲突或触及锁定时询问。

## 1. 定本轮范围与现行依据

输入：用户要求、已有作品路径与材料。先读当前根基、恢复入口和本轮相关成品；无已有文件时使用用户材料，不补历史形式。

明确要哪层、全书还是局部、作者锁定什么、哪些已是定稿正文。平台和篇幅已有就沿用；未记录平台时按番茄长篇默认（见 `资产/番茄平台.md` 第1节），在交付说明中注明可改。签约模式（连载／完本）未知且会改变交付形态时问一次，例如番茄 Lv.0、Lv.1 作者的新书当期只能走完本签约，就要规划到全书收束。其余仅影响当前结果的缺项集中问。作品输出未指定则使用当前授权工作区，不写进技能或知识库。

输出：本轮要交的文件与覆盖范围、可用依据和关键缺口。只要章纲就补够本段依据，不顺势扩成全书；要全套就记录全部范围，不能自行改成首批交付。

## 2. 倒推必要上游，取参考与作者材料

输入：目标产物及现行依据。章纲需要本段关键经历、转向依据和人物知识；幕纲需要人物当前处境与行动条件；阶段纲需要主线与阶段方向。只补真实缺口，不先造齐所有卡和索引。

有参考作品或相关库成果时，按第2.1节取用。作者直接提供原文可分析指定范围，但需要完整拆解入库时交给拆解技能。

### 2.1 仅在需要参考时取库

无需参考、作者材料已充分时跳过本节；不用先配置一个不会使用的库。需要参考时：

1. 写下本轮要解决的问题：信息、关系、事件、日常、规则、长线、经营或多线里的哪一种，以及要交的规划层。
2. 按 `库位置.md` 第4节解析库根。明确路径无效时报错，不静默降级、不改读过期快照；可与库无关地继续已授权的原创推导。
3. 读 `顶层认知.md` 的现行口径和用途边界。数字只信这里，不取技能示例或过期报告里的本数。
4. 若有 `骨架书候选清单.md`，按问题选候选；有题材词且存在 `题材映射.md` 时再读，它只连检索词、不提供默认参数。可选导航缺失时用已给卡路径或在授权库内定向定位，不阻塞也不通读全库。
5. 打开选中的主卡，先读阅读声明；卡首有「字段对应」时按它找对应内容。
6. 只取来源、阅读范围、驱动、已核过程和可迁移做法。目录候选、未读结论与未核转述保持候选；有新授权补读可更新状态，不能凭清理升级。
7. 精确事件、章界、引文或数字只在该卡已核范围内使用。没有原文或不在已核范围，就标未核，改用原创推导。
8. 把技法卡落到本书：① 说清它给读者的体验；② 按本书重造主角的所求与能力边界；③ 按本书世界重造对手的利害与可行回应；④ 舍弃原著专有的人物组合、道具与事件顺序。
9. 相关骨架、阅读卡、深拆按主卡链接和实际文件名另读。历史备份不作为现行结论。

停：本轮问题已有可用机制，或库没有对得上的卡。后者直接原创推导并标明待校准，不扫盘补书或通读全库。

输出：能支撑本轮设计的最小依据，以及“借何种机制、哪些内容重新设计”。缺库但作者材料足够可继续原创推导；关键方向仍缺就询问，不声称参考或市场验证存在。

## 3. 按依赖制作

### 3.1 根基：让人物行动可推

输入：作者材料、现行事实与参考用途。按 `资产/模板/story_foundation.md` 明确主线与体验、关键人物、规则条件、作者锁定与定稿事实；候选、未决和作废分开。

输出：`state/story_foundation.md`，供阶段与本段推演。复杂细目按需链接，不重复整份登记，也不把未来事件记成已发生。人物下一步推不出，就回动机与处境；规则支撑不了结果，就补可行条件。

### 3.2 阶段：建立约定范围的走向

输入：根基、本轮范围与已有整体安排。多卷时用 `资产/模板/volume_outline.md` 组织阶段任务、主要路径、重要变化和下阶段入口；单卷可直接在根基与单元安排中表达，不另建卷文件。

输出：必要的 `workspace/volumes/V01.md` 等。全套请求覆盖全部阶段，远端可以先粗但要继续细化到约定深度。卷数不由字数均值或断点数公式决定。

### 3.3 推进单元：让路径接得上

输入：根基、所属阶段和上一段结果或开局处境。使用 `资产/模板/act_outline.md`，按内容选幕、事件群、关系、探索或认知段。

推演具体行动、回应、选择或发现的依据、后果和继续路径。能协商就设计怎样协商，可顺利办成就不强造失败；关系与安静经历不强塞敌人或危机。

输出：`workspace/acts/A01.md` 等，含能推出章节的因果链。关键证据与策略来源确定，不能以“待正文发挥”代替；远端未决只阻塞依赖它的工作。

### 3.4 章纲：写到关键经历而非正文

输入：所属单元、相关根基、前章落点和本章知识边界。按 `资产/幕转章纲.md` 分章，使用 `资产/模板/chapter_outline.md` 展开实际经历。

写清行动、回应、重要选择与发现依据、结果与接续。主要场景不能只有“交涉成功”“感情升温”；专业过程若是场景核心给关键步骤，常规手续可略。关键转向核依据而非逐节点填五格；多样例见 `资产/章纲示例.md`。

输出：一章一份 `workspace/outlines/C001.md`。四块正文与视角、目标篇幅、锁定事实、人物知识边界头注；节点数和组织按实际需要，起承转合不是四拍配额。关键因果给足，措辞、微动作和现场对白留正文。章末可以完整收束。

## 4. 连读本批并修影响使用的问题

输入：本批成品与相关上下游。连读具体经历、转向依据和接续，再核本批涉及的规则、人物知识、资源、时间、情绪关系及重要未结。

发现问题定位来源：缺动机修人物，证据断修前置，路径断修单元；同时改受影响的未来章纲，不在末尾解释硬圆。触及作者锁定或定稿事实，列影响等裁决；与其无关的工作继续。

交付前按读者翻页顺序过一遍（刻度按本书节奏档位读，见 `资产/交接契约.md` 第7.1节）：
- 开篇是否尽早让读者看到人物的具体处境，而不是先背世界观？快爽档看前 300 字。
- 主角的独门卖点是否真正参与了破局（把书名职业或金手指换掉，故事就推不通）？推进主线的章能否指出卖点改变局面的那一拍？
- 对手是否按当场已知做出了合理反应，没有降智送高光？是否至少有一次主动出招，而不只是退让？
- 每章能否用一句话说出读者多得到了什么？稳推、慢燃档同样要说得出。
- 幕纲与章纲里的日期、第几天、金额、数量是否前后一致？
- 阶段胜利后是否留了在场享有的篇幅？受压时长是否合本档（快爽档一般不跨 2 章）？
- 相邻两章或两单元是否在重演同一种“阻拦—核查—过关”？

输出：能供下一层使用的本批稿与 `state/current_state.md`。后者明确规划完成/剩余、下一步输入和未决；正文快照只据实际定稿，无正文写无，不预填规划结果。已有正文时保留其快照与出处，规划只更新受影响的进度和接续区；正文回传的新事实只用于修受影响未来纲，不自动回灌公共库。

## 5. 分批、恢复与明确执行分工

大范围先有全范围阶段安排，再按自然单元批次制作；局部任务不要求先设计全书。每批保存文件，不以一条进度说明冒充产物，也不把批次结束当全范围完成。

恢复先读 `current_state.md` 和相关现行文件，修订先追受影响范围，不重放所有对话。

并发仅用于确实可分的读取或明确执行。主代理负责整体问题、设计、方法、任务边界与合并；跨技能或委派采用 `资产/交接契约.md` 的最小记录，给真实根路径与必要修订。子代理按具体文件、操作和产物指令执行，未决设计或原文冲突返回主代理，不独立选方向。同一文件只有一个写入者，共享根基不多人覆盖。

## 6. 交付与权限

输入：约定范围的成品。按 `资产/novel-writer交接格式.md` 交给 `novel-writer`，继续使用同一个作品根和现行文件；写作所需风格、编辑方法与硬边界入口由写作阶段按需补，不重建根基和章纲。按写作技能的实际接口交接。

交付说明包含完成范围、文件入口、未决与剩余，整套未完成就如实说。只交一层时，上游补足的必要依据也给入口。候选稿不冒充作者亲选，规划交付不授予正文写作、归档或投稿权限。

需要机械检查时运行 `python3 -B <实际技能根>/scripts/check_outline.py <作品根> --mode readiness --json`。`format` 检查四项头注、四块正文及编号；`readiness` 另查空值、显式占位符与可定位的本地文件坏链接。动机、因果、作者授权与真正可写性仍须连读判断。
