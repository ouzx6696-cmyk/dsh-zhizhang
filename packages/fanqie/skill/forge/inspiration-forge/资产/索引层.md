# 索引与引用：按需导航

成品保存故事内容；索引只帮助找到内容。短篇或单层交付可只用文件名和人物名字，不默认引入实体 ID、登记行或第二套数据库。

## 1. 优先引用现行文件

作品根中的基本入口是 `state/story_foundation.md`、`state/current_state.md` 与 `workspace/volumes/`、`workspace/acts/`、`workspace/outlines/`。卷层仅多卷需要，其他文件按交付范围创建。

章纲可在头注链接所属推进单元和前章；人物、规则直接指向根基相应小节。引用应让下一步读者知道去哪里，而不是只有一个无法定位的编号。

## 2. 什么时候使用稳定 ID

项目已经使用 ID 或名称频繁变化、跨文件引用复杂时可以沿用。常用 `CH-001` 人物、`RL-001` 规则、`TH-001` 线索，卷幕章使用 `V01/A01/C001`。现有约定优先，仅在导航确有需要时增加编号。

用了就保持一致，改名不随意改号。定义位置要可找到，但无需为每个对象各建一张卡。章纲四项必要头注（视角、目标篇幅、锁定事实、人物知识边界）不是可选索引；实体 ID、承接和出场登记才是按需导航，需要时写在头注，不单列成第五块正文。章纲容器见 `资产/novel-writer交接格式.md` 第3节。

## 3. 大项目的简要索引

翻文件已经困难时，可由现行成品整理“章号—上游文件—主要内容—状态”的导航。只记录链接和短摘要，不复制人物设定或整段因果链。内容变化时更新受影响项，不要求每批重建整库。

索引与正文冲突时回正文修订；没有索引生成器就由执行者整理，不声称自动注入、自动派生或持续同步。

## 4. 检查能力不能虚报

文件存在、编号区间、明确的路径引用可以机械核对；人物动机、伏笔公平性、角色是否误知或章节是否空转需阅读判断。

`scripts/check_outline.py` 可检查章纲头注、正文块、编号、空值、显式占位符及普通 Markdown 本地文件链接。实体 ID 定义、伏笔埋收配对与语义一致性由阅读核对。跳号可能来自节选，须结合约定范围判断。
