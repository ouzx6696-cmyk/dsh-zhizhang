# 规模参数：篇幅预算与工作范围

本文件只帮助估算交付工作，不决定故事结构或文学质量。沿用作者已给的篇幅；只有缺项会改变当前结果时才问，不每到卷纲阶段重复询问。

## 1. 先区分三种范围

- 故事范围：全书、某阶段或一段经历。
- 本轮交付：设定、阶段纲、幕纲、几章细纲或全套。
- 篇幅预算：目标总字数与单章预算；作者已给就沿用。作者未定单章时，番茄长篇默认可按约两千字估算并标“默认，可改”（社区常见经验，非平台规定，见第5节）；目标总字数未定就标未定。

“整套”要覆盖约定范围；若只有全书粗结构与近端章纲，就明确这样交付，不能自行称全书章纲已完成。

## 2. 章数估算

粗估章数为目标总字数除以单章预算。例如作者选定十万字、每章约两千五百字，可估约四十章；这是算术示例，不是平台建议或固定章长。

具体章界由主要经历的容量、视角和节奏决定。部分章可以较短或较长，调整后回看总预算；不能为凑章数删关键因果或让正文补凭空事件。

## 3. 卷与推进单元

多卷时按主线阶段、体验变化和自然断点安排卷。幕或实际单元数量由因果和内容决定，不从总字数除以历史平均幕长计算。

若引用拆解库的规模观察，注明原文范围、单位定义、已核边界与计量方式。不同切法或不同层级的数字不能直接混比。无现行样本就不提供题材均值；库内统计不作为默认参数。

## 4. 分批与恢复

交付量大时，先安排全范围阶段覆盖，再按自然单元逐批细化；只是局部请求则无需先设计全书。批次大小由上下文、单元长度和依赖决定，不固定每批几章或每份章纲多少字。

每批保存已完成文件、剩余范围、下一步所需输入和未决项。恢复时读入口与相关成品，不重放整个历史，也不把未写的规划事件当成已发生剧情。

## 5. 平台信息

番茄长篇的签约路径、推荐节点与治理要点见 `资产/番茄平台.md`，每条附来源与日期；签约、分发、福利与字数门槛会变，用前核对作家后台当期说明。作者另有平台时，使用作者约定或该平台当前官方说明，同样附来源与日期；作品中的常见章长不能反推平台规则。

平台节点影响规划的方式：完本签约要求整书写完再审，规划须有全书路线与收束；连载签约与推荐评估主要看前 2 万字与前 8 万字，首批章纲要让主线入口、关键人物动机和第一次推进兑现落在这一段里。节点数字只用来安排工作量，不决定幕数或章界。

本文件没有提供现行市场参数，也不引用短材料实验来证明中文长篇可完成或质量会提升。可执行的工作安排与已证明的创作效果是两回事。
