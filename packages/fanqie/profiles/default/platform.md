# 番茄连载要点

规划和写作需要平台取向、作者问签约或推荐、发布前检查、AI 声明时用。平台规则会变：下列条目整理自 2026-10-25 核对的公开说明，**一律以作家后台当期显示为准**；超过约三个月或与后台不符时，以后台为准并提醒维护者更新。签约、评估、发布、请假都由作者在后台操作，不代为登录或申请。

## 一、什么时候按番茄取向

| 作品状态 | 做法 |
|---|---|
| 根基已记录番茄 | 按本页 |
| 未记录平台 | 按番茄长篇默认，交付写“平台按番茄长篇默认，可改”；作者确认后再记入根基，默认值不算锁定 |
| 已记录其他平台、非连载或作者另选 | 本页只作对照；第五节 AI 标识仍适用 |

本书讲法、作者锁定、定稿事实优先于平台取向。签约模式（连载或完本）未知、且会改变本轮交付形态时，问作者一次。

## 二、开篇与前段要交出什么

平台签约标准写明的方向：开篇快速进入主线、主线清晰、层层递进；主角和重要配角人设与动机明确、出场推动主线；故事完整不烂尾。达到基础质量不等于一定签约，热门题材也不决定结果。

落到写作：

- 首章立住主线入口与主角处境（快爽档前 300 字见处境，见 rhythm）。
- 前段（连载首次签约评估材料约前 2 万字，需核实）让编辑看清题材、开篇、人设、代入感和主线。
- 推荐评估前（连载约 8 万字起可发起，需核实）：主线入口、核心设定的可见用途、主要人物动机，以及至少一次完整的推进与兑现，都已在正文发生。
- 完本签约路径：要全书路线和收束，发起前整书连读审读，主线、关键线、结局齐全。新作者可能只能选完本路径，开新书先问作者等级与所选模式（以后台为准）。

## 三、更新与篇幅

- 单章篇幅照章纲 `目标篇幅`。社区常见约 2000–2500 字一章，非官方，仅作作者未定时的起点；章纲检查对 1500–6000 字以外只提示不否决。
- 日更量、存稿量、全勤档位是作者的经营选择。可按作者给的数字做存稿算术，**不把更新字数当质量标准，不为达标扩写**。全勤与福利档位以后台当期公告为准。

## 四、低质治理症状对照

平台按“AI 粗制滥造、格式混乱、结构失常、空洞水文”治理。公告用语与本套方法的对应：

| 公告用语 | 查哪里 | 处理 |
|---|---|---|
| 行文冗余、空洞升华、无关的大段环境描写 | prose 病型“重复解释”“段尾感悟” | 删并没有新层次的说明，有体验用途的保留 |
| 词藻堆砌、句式呆板、语言模板化 | prose 病型表、本书声线 | 回到本书讲法重组，不靠换同义词或统一短句 |
| 前后脱节、逻辑错乱、主角前后不一致 | edit 硬伤：正文接续、人物认知、本书硬约束 | 核章纲、根基、定稿，解决前留草稿 |
| 流水账、转折突兀、情节片段化 | scene“跳步判据”、L1 结构 | 补亲历过程，或回规划补因果 |
| 重复堆砌、机械扩写注水 | 篇幅服从亲历价值 | 不为字数门槛扩写 |
| 格式混乱、未分段 | 发布前检查 | 见第六节 |
| 仓促收尾、关键线未收束 | 完结前整书连读 | 缺口回规划 |

这些检查是为了读者读得下去，不是降低 AI 检测率的手段，也不提供这类服务。

## 五、AI 参与与标识（所有平台适用）

依据《人工智能生成合成内容标识办法》（2025-09-01 施行）第十条：发布生成合成内容应主动声明并使用平台提供的标识功能；不得删除、篡改、伪造、隐匿标识，也不得为他人提供这类工具或服务。

- 交付含模型生成内容的正文时，提醒作者发布前按平台当期功能声明 AI 参与。番茄是否提供、怎样使用声明功能，以作家后台当期说明为准。
- 去“AI 腔”只为阅读质量。作者要求删除或隐藏标识、规避平台识别、把生成内容伪装成纯人工时，说明超出范围，继续做可做的质量修订。

## 六、发布前检查

作者说要发布或投稿时，对每章（或 `fanqie_assemble` 汇编的成稿）查：

- 正常分段，章节标题规范；
- 正文里没有模板栏、Markdown 符号、审读批注、占位符；
- 没有“人物此刻”“本章兑现”之类规划字样；
- 提醒 AI 参与声明。
