# 受控修订

按审读回报改稿、作者要求改某章、或修订已定稿章节时用。产出：一份审过的候选，获准后成为唯一现行正文，并同步受影响的根基。原则：**按真实授权改，不用表达优化偷改事实，只保留一个现行正文**。

## 一、先定位再动手

阅读症状 → 找原文与依据 → 判断哪层出问题（L1 结构、L2 场面、L3 句面，见 edit）→ 最小修改 → 回读组合后的全文。

- 问题来自章纲（缺证据、缺因果），回规划修章纲，不靠换词、补动作、强塞断章装饰空场景。
- “平”不等于要加反转；安静、直接心理、必要概括本身不是问题。
- 外部润色稿也是候选：先核事实、知识边界、声音、落点，再部分采纳，不整稿替换。

## 二、修订层级与授权

| 作者说的 | 允许动的 | 不许动的 |
|---|---|---|
| 润色、去 AI 腔、顺一顺 | L3，局部 L2 | 剧情因果、胜负、旧账、锁定 |
| 按回报改硬伤 | 回报列出的位置与最小修改方向 | 回报以外的大面积改写 |
| 重构、大改这一段 | L1、L2 病灶 | 作者锁定、其他已定稿章 |
| 改剧情、改结局 | 先报影响范围（后续章纲、已定稿章），等作者确认 | 未确认前一律不动 |

语义范围不明或会波及其他定稿时，先说明影响并问一次。

## 三、草稿修订（未定稿）

1. 取最新回报：`fanqie_review_get`，确认对应当前正文。
2. 编辑出候选：`fanqie_candidate_edit_brief` → 按 brief 改写 → `fanqie_candidate_edit_stage`。
3. 作者对编辑候选选择（`fanqie_candidate_edit_decide`）：
   - **A**：应用编辑并采纳为当前工作稿，须 `confirm_accept_after_edit=true`，采纳时自动扫描；
   - **B**：只保留候选，正式章不变；
   - **C**：拒绝编辑。
   不得静默选 A。作者已明确授权“改完直接用”时，不再索要固定确认词。
4. 草稿一变，旧回报失效：重审（edit），改过正文后 `fanqie_ledger_check`。
5. 前稿改动后，只重核依赖它的后稿与未来章纲。过期候选不能覆盖后来已修改的原稿。

## 四、已定稿章修订（例外流程）

普通采纳和定稿**永不覆盖定稿**。作者明确要求修订已定稿章时才走这里：

1. **记基线**：`fanqie_chapter_read` 取现行正文，记下当前 revision，确认授权范围。
2. **出候选**：同第三节，只出候选，不直接写正式章。
3. **审候选**：四类硬伤、差异核对、完整回读，并核授权涉及的上下游。差异里列明实际事实变化；只换表达就应保持同一事实。不能借用另一份候选的审读结论。
4. **更新现行稿**：`fanqie_chapter_save` 带 `force=true` 与 `expected_revision`（基线不匹配会拒绝，说明有人改过，先处理冲突）；或采纳编辑候选时 `fanqie_candidate_accept` 带 `force=true`。两者都弹作者确认，工具会保留历史并把该章降回草稿。
5. **重审再定稿**：降回草稿后重新审读，通过且作者确认后再 `status=final`。
6. **同步根基**：`fanqie_foundation_append_happened` 带 `replace=true` 更新该章后果；`threads`、`readerKnowledge`、`locks` 中受影响的条目用 `fanqie_foundation_set` 改。受影响的后稿和未来章纲标为需重核，不再当可信前提。

不为迁就旧的未来章纲倒改其他定稿；不自动重写其他定稿章。中途失败就保留候选，如实报告哪些已更新、哪些待同步，不自动回滚可能含他人改动的现行稿。

## 五、不应接受的“优化”

- 给关系戏补一个偷署名的反派让主角痛骂：改了事实和故事类型，不是润色。
- 给人物加“早已暗恋十年”：改了知识与关系前史，超出授权。
- 给安静章加“母亲悄悄吃药”的章末：用新增病情换悬念，破坏本章承诺。
- 把所有长句拆成单句段、批量删“觉得、好像、不是”：没诊断阅读问题，不算修订。
- 编辑阶段偷偷放宽规则或改章纲来让本章“通过”。

## 六、交付

说明：改了哪些位置、属于哪一层、事实是否变化、是否完整回读、当前状态（候选、草稿、待重审）、仍待作者决定的事项。
