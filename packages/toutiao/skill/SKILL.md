# 今日头条写作 · 4.0.0

把一条新闻、一份政策、一件日常事，或一个神话故事，写成一篇**能过审、像人写的、让读者觉得“说的就是我”**的头条图文或微头条。

**四条铁律**：生成靠处境，校验靠脚本，事实靠出处，终审靠人。

**目录**：本文件只做路由。`references/` 是各步方法；`corpus/` 是语料（资讯线按垂类，故事线在 `corpus/story/`）；`templates/` 是立项卡和交稿单；`scripts/rules.py` 是**唯一规则源**，文档不抄数字，跑 `python3 scripts/qa_check.py --rules` 看现行规则。路径相对本技能目录；交付物写到工作区 `outputs/toutiao/`。只依赖 Python 3 标准库。

## 一、骨架：两条内容线 × 一个默认体裁

| | 资讯线 | 故事线 |
|---|---|---|
| 题材 | 热点、政策、生活实用 | 神话、传说、民间故事、各国神话改编 |
| 找题 | `s1-hot.md` | `s1-evergreen.md`（节日、影视热播、展览考古） |
| 打分 | `s2-selection.md` 第二节 | `s2-selection.md` 第三节（时效看节点） |
| 主驱动 | 账本型 / 处境型 / 冲突型 / 信息型 / 情感型 | 故事型 |
| 写法 | `s4-common.md` + `s4-news.md` | `s4-common.md` + `s4-story.md` |
| 语料 | `corpus/common.md` + 对应垂类 | `corpus/story/motifs.md` + `corpus/story/texture.md` |
| 防撞 | 开头式结尾式、人名、同赛道同日、账本型过半 | 30 天同故事或同母题、连续同一改编方式、开头式结尾式 |

**体裁**：默认**长图文**（主稿约 2000 字回答“主问题”，延伸约 1000 字接住主稿留下的“下一个问题”，两个问题立项时一起定）；用户要短稿或下一个问题离读者太远时用**短图文**；抢一个侧面用**微头条**（`s4-micro.md`）。

## 二、三件贯穿全程的东西

| 东西 | 在哪 | 谁写、谁读 |
|---|---|---|
| **立项卡** | `outputs/toutiao/YYYY-MM-DD-slug/立项卡.json`（模板 `templates/brief.json`） | S2 写；S3、S4 照它写；S6 `qa_check.py --card` 核对；S7 `ledger.py add` 记台账 |
| **发稿台账** | `outputs/toutiao/log.csv` | S7 用 `scripts/ledger.py` 记；S1、S2 先读；`--card` 自动查撞车撞题 |
| **反馈记录** | `outputs/toutiao/feedback.md` | 用户改稿后追加“原文 → 改后 → 动机”；每次开工先读 |

## 三、路由

| 用户手里有什么 | 走哪条路 |
|---|---|
| 无题材，要追热点 | S1 热点雷达 → S7 |
| 无题材，要神话传说或节日题 | S1 常青题 → S7 |
| 已给题材、通稿、政策原文、某个故事 | S2 → S7 |
| 要写微头条 | S2 → S7，S4 用 `s4-micro.md`，质检 `--mode micro` |
| 已有成稿，要去 AI 味或润色 | S5 → S6（需要交稿再走 S7）；没有立项卡先补一张简版 |
| 只要标题、选题评估、质检 | 单跑 S3 / S2 / S6 |

**动笔前对齐**：一次最多问两件事，挑最影响结果的（资讯线：题材来源、人群；故事线：哪个故事、哪种改编方式）。默认单篇直出，用户要比选才出候选池。

## 四、七步

| 步 | 读 | 做 | 产出 |
|---|---|---|---|
| **S1 找题** | `s1-hot.md` 或 `s1-evergreen.md` | 热点：`python3 scripts/fetch_hot.py --top 30 --relevant --json hot.json`，退出码 2 改用网页搜索，再不行请用户粘贴热榜；常青题：节点日历 + 台账撞题筛 | 候选清单 |
| **S2 立项** | `s2-selection.md` + 台账 | 分线 → 按线打分 → 定主驱动、体裁、主问题与延伸（接的问题、接法、出处）→ 填立项卡 | 一行摘要 + `立项卡.json` |
| **S3 标题** | `s3-headline.md` | 五母体各一版，四问排序，34 字硬上限；回填立项卡 | 1 主 4 备 |
| **S4 成文** | `s4-common.md` + 本线写法 + 语料 | 先排蓝图，主稿和延伸照同一张蓝图写；过自检，能机检的先跑 `--card` | 初稿（初稿待改） |
| **S5 红笔** | `s5-editing.md` | 骨架 → 信号 → 16 病型 + 故事线 4 病型 → 人味与节奏 → 防误杀 | 三联表 + 终稿（待验收） |
| **S6 质检** | `s6-qa.md` | `python3 scripts/qa_check.py 终稿.md --card 立项卡.json`；过线 = overall ≥ 84、零 fail、无硬闸；打回最多两轮，不靠换词、堆口语词或数字凑分；再过九项人工速查 | 脚本原样输出 |
| **S7 交稿** | `s7-delivery.md` + `templates/交稿单-图文.md` | 交稿单写入 `outputs/toutiao/…/交稿单.md`；对话里直接给终稿和标题矩阵；`ledger.py add --card … --status 已验收` | 交稿单（已验收） |

**汇报**：S1~S4 每步一行摘要；S5 给三联表；S6 贴脚本原样输出；S7 交完整成稿。状态词只用 `初稿待改 → 待验收 → 已验收 / 验收退回 → 已交稿`；用户明确采用后才改成已交稿（`ledger.py status --to 已交稿`）。交稿单末尾固定一句：**“——AI 到此止步。是否采用、何时发布由你决定。”** 不替用户发布、不登录头条账号，除非用户明确要求。

## 五、真实性与平台底线（高于任何技巧，违反就不交）

1. **硬事实有出处**：政策、金额、日期、机构、原典与版本，只来自用户素材或本次打开核实的页面，写进立项卡。搜索摘要、`corpus/` 都不算出处。查不到就坦白说。
2. **不冒充亲历、不把神话写成史实**：合成人物用明示口吻；故事线不写“考古证实”“真实存在”，不用亲历口吻包装。
3. **网友声不造假**：真实转述标平台，没有就概括，不编昵称和原话。
4. **延伸是扩写不是拼接，故事不照搬原典和百科**：头条《首发激励计划》（2026-05-25 更新）把拼接要点、整合汇编、大篇幅引用公共信息判非原创，空洞水化、事件重复描述、网络信息拼凑、模板化标题算低成本内容；2026-09-15 治理 AI 低质内容公告对换题材换人物、套同一模板反复发从严处置。
5. **发布设置提醒到位**：单篇勾“头条首发”由用户决定（原创、72 小时内只发头条并关掉内容同步授权、不重发、违规后果）；声明勾“AI生成”（《人工智能生成合成内容标识办法》2025-09-01 施行），故事线和用了合成人物的稿子还勾“虚构演绎，故事经历”（头条 2025-11-27 公告）。细则见 `s7-delivery.md`。
6. **去 AI 味为了好读，不为躲标识**：不以骗过检测为目标，不建议删平台加的 AI 标识。

## 六、改技能本身

- 改评分、词表、预算、内容线、母题：只改 `scripts/rules.py`；判定逻辑在 `scripts/qa_check.py`；抓榜在 `scripts/fetch_hot.py`；台账在 `scripts/ledger.py`。新增母题要同时补 `corpus/story/motifs.md`。
- 改完跑 `python3 tests/test_gates.py`，全过才算改完；在 `CHANGELOG.md` 记一笔；同步 Hark 技能库里的说明文字。
- `feedback.md` 里同类动机满三次，提醒用户固化进 references 或 corpus。

## 七、避坑

1. **槽位只用 `[方括号]`**：任何 `{xx}` 都判未替换占位符。
2. **只用规范中文标点**：引号“ ”‘ ’，不用「 」、半角标点、~、·、★，正文不留 `**`。脚本按硬闸查，细则 `s4-common.md` 第三节。
3. **分数是底线不是目标**：脚本测得到套话、节奏、数字、重复，测不到真假和好坏。
4. **账单味先查主驱动**，**同质化先查台账**：病根多半在骨架和选题，不在句子。
5. **示例不是素材**：示例人名、句子、语料数字照搬，是撞脸和失实的头号来源。
6. **时间窗、露出字数、打分权重是经验值或本技能自定**，写进交稿单时注明。
