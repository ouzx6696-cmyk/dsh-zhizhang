# S4 微头条写法（可选体裁，两条内容线都能用）

> **什么时候写微头条**：热点刚冒头、来不及写完整图文时抢一个侧面；一个现场、一句话、一张图就能立住的小切口；给后面的长图文预热、试评论区风向。
> **和图文共用的**：标点、纪律、真实性底线见 `s4-common.md`。
> **和图文的区别**：没有标题，没有小标题，首句就是标题。篇幅短，节奏更快，但“人、动作、反常”和真实性底线一条不少。
> **篇幅是经验值**：300~1000 字最常见，平台本身允许更长。`qa_check.py --mode micro` 按 300~1000 字给提示，不在档内只扣 4 分，不否决。

---

## 一、结构：一句钩子 + 一个现场 + 一个转折 + 一个问题

| 位置 | 字数 | 要做的事 |
|---|---|---|
| **首句** | 8~30 字 | 信息流里露出来的就是它。人 + 正在做的事 + 一个反常，或一句原话。脚本拿它当标题打分 |
| **现场段** | 1~3 段 | 把首句的反常落到一个具体场景：在哪、手里拿着什么、说了什么 |
| **转折段** | 1~2 段 | “可他说完又补了一句”“后来才知道”——给读者一个没想到 |
| **落点段** | 1 段 | 停在一个动作或一句实在话上，不总结，不升华 |
| **提问** | 1 句 | 带 `?`，让人想说自己家（“你家附近还有这样的老摊子吗？”） |

- **段要短**：4~8 段，每段 1~3 句。手机一屏看完两三段最舒服。
- **配图**：1~9 张，写成【配图：画面描述】标记，脚本记作配图，不算字数。
- **数字更省**：全文 0~2 个数字。主驱动规则照旧，微头条几乎不写账本型。

## 二、首句六式（和图文冷开场对应，换着用）

1. **现场动作**：“楼下修鞋的老钟，今天把摊子往里挪了半米。”
2. **原话顶门**：“‘这钱我不要了，你们别再打电话了。’社区网格员说，这是她这礼拜第三次听到这句话。”
3. **反常结果**：“全楼就三户没签加装电梯同意书，其中一户是牵头的那家。”
4. **身份点名**：“替爸妈办过异地医保备案的，可能都卡过同一步。”
5. **时间节点**：“离今年医保缴费截止还有一个礼拜，我妈的那份还没交。”（日期必须核实）
6. **直球判断**：“说句可能挨骂的：社区食堂贵两块钱，不全怪食堂。”

## 三、故事线的微头条

一个原典细节 + 一个画面 + 一个问题就够了：“《山海经》里精卫的叫声，就是在喊自己的名字。”然后一两段讲这句话为什么让人停下来，最后问一句。版本和出处的规矩照 `s4-story.md`，不写成“冷知识合集”（那是拼凑汇编）。

## 四、禁区（比图文更容易踩）

- **不写成亲历冒充新闻**：“我表弟上周刚提了 3200 块”这种第一人称硬事实，没有真实案例就不能写。合成人物用明示口吻，或在发布时选“虚构演绎，故事经历”（见 s7-delivery.md 第九模块）。
- **不拿热点人物编段子**：涉及真实的人（明星、当事人、官员），只用公开报道里的说法。
- **不靠情绪词撑场**：短文更容易写成“太心酸了”“看哭了”，一律换成动作和物件。
- **不拿结尾求关注**：“点个关注不迷路”“转给需要的人”不算互动引导，诱导分享还会命中合规词。

## 五、质检与交付

```bash
python3 scripts/qa_check.py 微头条.md --mode micro
```

- 不需要 `--title`，也不需要 `#` 一级标题；文件第一段的第一句就是首句。
- 结构分不看小标题，看段数、配图、互动句和篇幅。
- 通过线和图文一样：`overall ≥ 84`、六维零 fail、无硬闸。
- 交稿单用 s7-delivery.md 第三节的精简版（首句 1 主 2 备）。

## 六、标杆（`tests/fixtures/micro_good.md`，`--mode micro` 实测 88 分）

```
楼下修鞋的老钟，今天把摊子往里挪了半米。

不是城管来了。是隔壁新开的奶茶店排队，队伍一长就挡住他的小马扎。……

老钟那天收了她十块钱，比平时少要了一半。……

你家附近还有这样的老摊子吗？评论区说说。
```

拆解：首句见人、见动作、见反常（挪了半米）；第二段先否定读者的猜测（不是城管）；转折放在“可他说完又补了一句”；全文只有“十块钱”“五年”“三年四茬”几个顺手的数；结尾停在晒白的硬纸板上，再抛问题。老钟是合成人物，真发稿要另起名字并按 s7-delivery.md 选声明。
