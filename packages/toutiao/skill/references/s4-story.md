# S4 故事线写法：神话、传说、民间故事、各国神话改编

> **先读** `s4-common.md`（长图文蓝图、开篇、标点、节奏、纪律、真实性）。本文件只写故事线自己的东西：平台边界、改编方式、版本与出处、三力怎么落到故事上、开头结尾的写法。
> **语料**：`corpus/story/motifs.md`（母题库：每个母题的代表版本线索）和 `corpus/story/texture.md`（写法质感）。母题库里的版本只是线索，**动笔前必须核实原典**。
> **主驱动**：故事型。讲情节和人物，数字够用就行（年代、卷次都尽量少，预算跑 `--rules` 看）。

---

## 一、平台边界（先看，违反就不交）

1. **原典没有版权，复述原典也不等于原创。** 头条创作者帮助中心《首发激励计划》（2026-05-25 更新）把“罗列常识、拼接要点等整合汇编”和“大篇幅引用他人内容或公共信息（含百科知识）”判为非原创。照着百科把情节顺一遍，就是这一条。原文引用只用短句点睛，每处一两句；全文引用控制在一成以内（本技能自定的口径，不是平台数字）。
2. **不把神话包装成史实或亲历。** 头条 2026-09-15《关于升级治理AI低质内容的公告》重点治理“模板化拼装、套路化表达”“虚构包装纪实”“内容空洞失真、叙事无法自洽”。不写“真实存在”“考古证实”“史书记载确有其人”（脚本会扣分提示），除非本次打开的页面这么写，而且要写成转述；不用“我奶奶亲口讲过”这类亲历口吻包装合成情节。
3. **同一个账号别一套模板写到底。** 同一公告对“更换题材人物、替换表达模板”反复发同质内容从严处置。换个神、换个国家、套同一个骨架，就是这一条。台账里同一条线的上一篇，开头式、结尾式、改编方式都要错开；30 天内不写同一个故事或同一个母题（脚本会查）。
4. **声明两项都要勾。** 神话、民间故事、文学改编属于“虚构演绎，故事经历”（头条 2025-11-27《“故事内容”的规范标识公告》）；本技能产出的稿子还要勾“AI生成”（《人工智能生成合成内容标识办法》2025-09-01 施行）。只能单选时按 `s7-delivery.md` 处理。
5. **宗教、少数民族史诗、真实历史人物另当别论。** 这几类不按神话改编写；要写就当资讯线或文化观察，事实全部有出处，不演绎。

## 二、改编方式（三选一，写进立项卡“改编方式”）

| 改编方式 | 怎么写 | 适合的题 | 延伸常用接法 |
|---|---|---|---|
| **原典重述** | 以一个版本为骨，补场景、动作、对话，情节不改 | 读者知道名字、不知道细节的故事 | 原典与流行说法 |
| **视角改写** | 换一个配角、反派或旁观者讲，原情节不动，动机和感受是新的 | 人人都熟、正面讲已经讲烂的故事 | 原典与流行说法 |
| **母题对照** | 一个母题讲深一个版本，再引出别国的同类故事 | 大洪水、射日、盗火、冥府寻人、变形 | 别国同母题 |

**改编的底线**：情节骨架忠于你选的版本，补的是细节，不是新的大事件。要大改（换结局、加人物），标题或开头就说明是“新编”，不冒充原典。

## 三、版本与出处（神话的“硬事实”）

- 神话版本多，**先定用哪一版**，写进立项卡“所用版本”和“出处”：中国古籍写书名加篇名，外国神话写原典或通行译本。
- 只引用本次打开核实过的原文或可信的整理页面；记不清原文就转述，**不编“原文”**，不编卷次。
- 两个版本说法冲突，就写“另一种说法是……”，别替古人圆。
- 母题库里的线索、你记得的“常识”、搜索摘要，都不算出处。

## 四、三力怎么落到故事上

- **切身力**：给神话人物一个今天的人也会碰到的处境，藏在情节里让读者自己对上号，不贴一句“这告诉我们”。射下太阳的人，功劳最大反倒最先被冷落；追日的人，是认准了一件事、谁劝都不听的那种倔。
- **照镜子力**：神也要有账之外的东西，一个习惯、一个怕、一个只有它自己知道的理由。补细节从原典的缝里找：原典写了什么、没写什么，没写的地方就是你能补的地方（方法见 `corpus/story/texture.md`）。
- **评理力**：故事线最容易写成说教。不总结寓意，停在一个画面或一个两难上，把“你怎么看”留给评论区。

## 五、开头与结尾（和故事线上一篇错开）

| 开头式 | 写法 |
|---|---|
| 定格画面 | 从故事里最有画面的一刻切入：刑天断首后还在挥斧，一只鸟把一粒石子丢进海里没有声响 |
| 原典一句 | 先摆原典里最短、最狠的一句，再说这句背后被跳过的东西（只用短句） |
| 反常结局 | 先说结局里反常的地方：功劳最大的人最先被冷落、原典根本没写海填没填平 |
| 配角开口 | 让一个旁观者、配角、反派先说一句，视角改写常用 |
| 直球亮底牌 | 先亮一个和流行说法不一样的判断，再拿原典去兑现 |

| 结尾式 | 写法 |
|---|---|
| 画面留白 | 停在故事里的一个画面上，再问一句读者 |
| 两难选择 | 把故事里的两难摆给读者：换你，你搬不搬 |
| 经历共鸣 | 问读者身边有没有这样的人、这样的事 |
| 观点碰撞 | 有人说傻，有人说倔，你怎么看 |
| 古今对照 | 把古人的做法和今天的一个具体场景并排放，不下结论 |

## 六、长图文结构（主稿约 2000 + 延伸约 1000）

**主稿**：
1. 引子三段：开头式 → 主角入场（原典给的样子 + 一个你补的细节）→ 一句亮底牌。
2. 三到四节讲完一个版本，每节一个推进：起因、卡住、选择、代价。小标题像说书人的一句话，不用四字对仗。
3. 主稿最后停在画面上，不总结；最后一两段留个口子，引出延伸要接的问题。

**延伸**（规则见 `s4-common.md` 第一节）：接住主稿留下的那个问题，三种接法——
- **别国同母题**：先找到真正可比的那一点，再讲不同；不同之处为什么有意思才是重点，不是把别国故事从头复述一遍。
- **原典与流行说法**：原典写了什么，动画、电影、课本、俗语把它改成了什么，改了以后丢了什么。只谈公开信息。
- **今天的痕迹**：节日、地名、习俗、博物馆藏品（要有出处，不往上牵）。

主角在延伸里继续出场：拿别国故事回头照它，或者从它的一个细节再往下走一步。延伸不重讲主稿情节，脚本会查重合度。

## 七、故事线自检（在 `s4-common.md` 第八节之外）

- [ ] 立项卡写了改编方式、母题、故事、所用版本和出处；原典核实过。
- [ ] 情节骨架忠于所选版本；补的细节没有改变大事件；大改的标了“新编”。
- [ ] 原文引用短句点睛，没有成段照搬原典或百科。
- [ ] 没有“真实存在”“考古证实”这类无出处的史实化说法，没有亲历口吻。
- [ ] 没有“这告诉我们”“启示我们”式的寓意总结。
- [ ] 延伸接住主稿留下的问题，主角在延伸里继续出场，不重讲主稿。
- [ ] 开头式、结尾式、改编方式和故事线上一篇错开；30 天内没写过同一故事或母题。
- [ ] 交稿单提醒勾“虚构演绎，故事经历”和“AI生成”。
