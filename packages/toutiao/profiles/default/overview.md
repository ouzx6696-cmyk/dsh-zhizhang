# 头条写作总览：从哪步起、每步做好的关键

开工、换步或拿不准下一步时读。七步与工具的对照表在常驻总则里，这里补路由、每步的关键和工具的真实行为。

## 开工

1. `toutiao_feedback_read`：作者以前怎么改你的稿，照着避开。
2. `toutiao_article_list`：有没做完的就接着做，别另开。
3. `toutiao_ledger_show`：看最近发过什么，资讯线看 10 篇，故事线看 30 天。

## 从哪步起

| 作者给了什么 | 从哪步起 |
|---|---|
| 什么都没给，要追热点 | S1，s1-hot |
| 要写神话、传说、节日题 | S1，s1-evergreen |
| 题材、通稿、政策原文或一个故事 | S2 |
| 一篇成稿，要润色 | 建文章、补简版立项卡、存稿，再 S5、S6 |
| 只要标题、选题评估或质检 | 单跑 S3、S2 或 S6 |

动笔前最多问两件：资讯线问题材来源和人群；故事线问哪个故事、哪种改编方式。能查到的不问。

## 每步做好的关键

| 步 | 关键 |
|---|---|
| S1 | 先过红线再看热度；跨平台共振的优先；常青题先查撞题 |
| S2 | 写不出“延伸.接的问题”就改短图文；`toutiao_card_set` 返回的 fail 当场改掉 |
| S3 | 五个母体各一版，四问排序，不按分数排 |
| S4 | 先排蓝图再动笔；数字按主驱动预算给；直接引语至少五处 |
| S5 | 先骨架后句子；三联表写病型编号 |
| S6 | 先清硬闸，再照 fails 定向改，两轮内过 |
| S7 | 交稿单正文与当前稿逐字一致；作者确认前不叫“已交稿” |

语料：资讯线 corpus-common + corpus-[垂类]；故事线 corpus-story-motifs + corpus-story-texture；想看一篇过线稿取 corpus-benchmark。解释分数时才取 `toutiao_rules`。作者自备资产用 `toutiao_method_get` 传 list 查看，只作参考。

## 工具的真实行为

- 每存一版稿，状态回到“初稿待改”，旧质检作废；改立项卡或标题也让旧质检作废。标题和卡定好再跑终检。
- 正常顺序：存终稿 → `toutiao_status` 待验收 → `toutiao_qa_check` → 过线改“已验收”；不过改“验收退回”，改完再存稿、再送、再查。
- 插件配置要求“须经编辑红笔”时，写手自己存的版本送不了待验收。
- 交稿单只收“已验收”且质检仍有效的稿；之后记台账；作者确认后才能改“已交稿”，台账状态随之同步。
- 作者亲手改的版本存时标 role=author，并用 `toutiao_feedback_append` 记下动机。

## 三条经验

1. 账单味先查主驱动，同质化先查台账。病根多在骨架和选题，不在句子。
2. 示例人名、语料句子和数字不是素材，照搬就撞脸、失实。
3. 质检测得到套话、节奏、数字和重复，测不到真假和好坏。
