# 0.9.6 迭代方案：闭合工作流，进入真实项目测试

日期：2026-11-02（香港时间）。基线为正式 0.9.5、master `8834aaf`。依据：[PI、模块及交互审核](0.9.5-WORKFLOW-READINESS.md)。本文件是待实施方案，不代表下列验收已经完成。

## 1. 版本目标

0.9.6 交付后，作者可以从首次配置开始，在两个项目、两部小说或两篇文章之间工作，可靠地知道：**现在看的是什么、任务处理什么、模型能写哪里、结果基于哪一版、失败后如何继续。**

继续基于 PI 1.4.0 和自有业务开发。沿用工作台布局、工具业务能力、方法资产、文件格式和 journal。范围集中在作用范围、会话、任务、版本、模型连接与上手流程；不扩张其他 Agent 适配，不更换状态框架，不重建存储和测试平台。

模型适配列为本版必做：精简复用 PI 已有的 provider、API、模型目录、上下文和思考能力。我们负责桌面呈现、角色选择、配置保存和必要转换，协议执行与能力判断优先调用 PI。

## 2. 统一认知与最小执行契约

在现有 Target、Focus、SessionEntry、Task 与事件上补齐职责，不额外建设一套运行平台：

```text
作品范围：mode + 规范化项目根 + 小说 work / 文章 id
对话身份：作品范围 + 当前 PI 会话身份
任务身份：一次发送的 id + 作品范围 + 对话身份 + 读取依据 + 当前状态
```

- 模型、公共方法库可共享，作品私有对话和写入范围按上述契约隔离。
- 浏览位置不改变已接受任务；返回结果可引导跳转，但不能偷偷变更另一任务的对象。
- 新书／新文章在创建完成前属于明确的创建任务，完成后绑定到新对象。不要将“没有作品”当作可以随意操作任意作品。
- 默认只操作当前作品。跨项目参考或批处理需要明确任务入口；0.9.6 先阻止未声明的越界，不做复杂多项目授权系统。
- 任务至少表达 preparing、queued、running、stopping、settled；SDK 的 streaming／compaction 作为执行状态来源，不能独自决定应用任务是否仍存在。

## 4. 分批实施与工作指导

第一至第四批是本版必做项，按顺序处理依赖；第五批核对整体结果并交付。每批沿用现有模块修改，不先抽象一套通用框架。

### 第一批：先封住作用范围与目录身份

**范围**：session 工具包装、项目路径解析与登记、Target／Focus、会话 key、主子角色目标。

1. 在任何有副作用的路径解析／登记之前校验作用范围。绑定 work、article 和根目录不可被模型参数覆盖；工具传相同值可接受，传其他值明确失败。
2. 为读取和写入区分目录清单与作品内容。目录导航需要的列表不授权读取或修改另一作品；引用资料只按本次明确来源读取。
3. 消除 working_dir 改 base 而保留旧 worksRoot 的混合结果；失败请求不得更新其他项目登记或自动创建其目录。
4. 复用同一物理路径规范化：已有目录以 realpath 为基础，按平台文件系统语义处理大小写，不在所有平台统一转小写。
5. 会话 key、项目登记、事件范围和租约使用同一身份口径。保留既有会话与项目索引的兼容读取；别名产生的旧对话入口可查，不静默合并或复制私有聊天。
6. 规划和编辑同样绑定范围。创建流程只把实际新对象绑定回父任务，不因模型临时 open 其他 work 改变已有任务归属。

**验收**：A 会话不能改 B；拒绝 working_dir 越界后，A/B 文件及登记均保持；同物理根的常见别名不会创建独立任务范围；实际不同的大小写敏感目录不被合并。Windows 路径行为单独确认。

### 第二批：贯通作品、对话与完整任务

**范围**：Sessions、delivery、history、editor-task、task-tracker、IPC 契约、controller／chatStore。

1. 头条文章 id 进入任务和对话身份。旧目录级会话保留为“旧目录对话”，可查阅，不自动复制进每篇文章的新模型上下文。
2. 现有 preparation 改为能按作品／任务管理的记录，任务在上下文读取前就可见、可取消。保留取消覆盖 SDK 接收前后间隙的已有实现。
3. release、newConversation、stop、dispose、模型／搜索设置重建使用一致的任务归属判断。选择保留后台任务或取消后释放，任何路径都不能留下已移出管理却继续发起的请求。
4. 排队要求显示已接受、所处理对象及取消范围；准备失败要回到明确失败状态。无需持久化通用任务队列。
5. 事件带作品与对话／任务身份，界面据此投影。历史视图不接当前 stream／busy／task；当前任务可在独立状态条显示。
6. 历史模式下，发送、快捷按钮、命令面板、键盘入口共同执行只读规则，并提供“返回当前对话”。只禁用一个按钮不算完成。
7. 当前 SDK 会话文件和作品事实仍分别保存。重启后识别上次中断及 pending journal，展示已保存结果和检查入口；不自动重放旧写入或自行续跑模型。

**验收**：复现准备中切页、新对话和停止后，无游离请求；两篇文章的私有要求不串；查看历史时当前流不混入，所有任务入口遵守只读；排队和后台任务能找到并停止。

### 第三批：复用 PI 模型能力，固定内核配置与稿件依据

**范围**：models、pi-adapter、模型 IPC、createSession、prompt、角色工具、ArticleStore／长篇写入入口、审读交接；设置界面在第四批使用同一结果。

**模型连接与能力：**

1. 扩展现有 pi-adapter，直接使用 ModelRuntime 的 provider／模型查询、可用性及刷新接口。模型类型、思考能力和接口标识以安装的 PI 为依据；PI AI 的必要能力也经这一边界接入。主进程给 UI 返回所需元数据，渲染进程保持轻量。
2. 地址使用一个完整 baseUrl 输入，示例说明协议、主机、端口和基础路径，例如 OpenAI 兼容本地连接 `http://127.0.0.1:11434/v1`。保留代理前缀，按所选 PI API 的规则使用路径，提示不要把完整生成端点当基础地址。
3. 补充可见的 API 类型选择。常用项包括 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Google Generative AI；选目录模型时沿用其 API，其他 PI API 按实际需要展示。请求和流式工具调用继续交给 PI，不复制 SDK 协议代码。
4. 模型列表可搜索、刷新，并可手填。内置模型复用 PI 目录与缓存；已有动态 provider 复用 refresh；自定义兼容网关支持模型列表端点时，仅通过 PI 的发现接口补最小请求／解析。失败保留现有配置和列表，允许继续手填，不做后台轮询或通用发现平台。
5. 区分目录更新与当前端点的模型抓取，界面标明来源。只返回 ID 的接口不据此猜出容量、思考能力或调用权限；缺少元数据时明确使用待确认的默认值／手动配置。
6. 默认上下文和输出上限采用 PI 模型描述，允许用户显式覆盖；切换模型时重新取得其元数据，检查保留的覆盖值是否仍适用。运行时保留 thinkingLevelMap、compat 和已有费用数据，不再统一拼装丢失能力的模型。复用 PI 的压缩和预算逻辑。
7. 思考档位使用 PI 的 getSupportedThinkingLevels／clampThinkingLevel 或会话提供的同等能力。非思考模型不提供无效选择；xhigh、max 等仅在支持时出现，切模型后显示实际生效档位。自定义模型允许在高级配置中明确能力和映射，不凭模型名称臆测。
8. 写手、编辑、规划使用相同连接语义；角色可沿用连接并保持独立会话。沿用现有凭据保存和脱敏方式；明确配置的无 Key 本地连接按其 PI 认证声明处理，不一律要求付费服务 Key。0.9.5 的自定义地址、端口、Key、模型和用户覆盖迁移后可用；模型配置不从项目目录隐式导入。
9. 常用服务商只作便捷入口，来源优先使用 PI；保留本产品必需的少量预设即可。模型枚举不等于连接成功，连接检查与真实任务走同一 PI 配置。暂不扩大为所有云平台登录、OAuth 或全协议验收工程。

**内核与稿件依据：**

1. 显式关闭 SDK 隐式 context files，保持内置编码工具、extensions、skills、templates 的现有边界。作者偏好和方法从本产品已有入口进入。
2. 使用明确的 SettingsManager 配置并供资源加载与 SDK 会话共同使用。优先用 SDK 现有内存设置能力，约定压缩／重试等必要值；不另做一套设置框架。
3. 当前项目或上级目录的 AGENTS、.pi/settings 不得静默改变写作提示或关闭压缩。用户需要导入这些材料时，应通过明确的产品入口作为材料处理。
4. 任务捕获方法选择，约定任务中途切换在下一任务生效；方法工具与任务说明使用相同方案。资料库共享保持可见，不把全局开关暗当项目私有状态。
5. 把 Agent 存稿的版本条件贯通到既有存储临界区。初稿创建、改稿和审读产生的新稿应分别核对原依据；读取后作者改过，保留模型稿作为候选或返回冲突，不能直接推进为当前稿。
6. 优先复用头条 stageDraft 的 expected 条件与长篇 expected_revision／候选依据。新增必要的工具参数和返回版本，避免为了补依据再建第二套内容数据库。
7. 明确审读路线：0.9.6 默认审读已保存工作稿；候选视图提示先采纳为工作稿，或明确说明此次审读的是现行正文。直接审候选的完整新回报体系不作为本版扩张项。
8. UI 保存、Agent 保存、审读回报和作者定稿应沿同一版本事实判断。显式定稿和危险覆盖继续使用已有作者确认。

**验收**：UI 选择和实际请求使用相同模型、API、容量及思考档位；PI 模型元数据保留，自定义端口和代理路径有效，旧连接可用。AGENTS 与 .pi/settings 标记不会隐式进入新会话；已有编码工具仍未开放；旧依据模型稿不能顶替作者新版成为当前稿；编辑结论对应界面明确显示的正文版本。

### 第四批：闭合上手与日常交互

**范围**：Onboarding、ModelFields／Settings、空态、项目切换器、Agent 状态及稿纸操作。

1. 首次配置与设置共用精简的 ModelFields：选服务商／自定义连接 → 确认地址和 API → 选取／抓取模型 → 按需调整上下文与思考 → 检查连接。高级字段折叠；提供“编辑沿用写手连接／单独配置”的明确选择，保持编辑独立上下文。
2. 分别显示写手与编辑就绪状态。只有写手已配置时，审读入口说明缺什么；不要等第一次委派才报 Key 错误。
3. 连接检查明确验证范围；在进入项目测试前，对实际配置做一次短的流式工具调用走查。用无作品副作用的工具，不建立全供应商探测矩阵。
4. 修复无目标空态“开始设置”，已有根／旧目录打开后能回到可操作状态；引导的已有作品入口要能找到或打开实际目录。
5. 显示当前项目、作品、对话模式及正在执行任务的对象。准备／排队期间也有反馈，不把空白当成没有任务。
6. 未发送要求至少在切换作品时保留或明确处置；当前实现的局部输入不应无提示消失。优先在已有状态中按范围保存，不做全文自动存档系统。
7. 错误说明给出对象、实际保存结果与可继续动作；历史模式、只读作品和版本冲突各有明确文案。
8. 保持现有三栏与稿纸布局，优先修复行为；不安排整套视觉重做、动效或组件库迁移。

**验收**：新用户能配置两角色、选根、开书／文章并进入可操作界面；已有配置但缺目标也能恢复；当前对象与后台对象清楚，未发送要求不无提示丢失。

### 第五批：冻结候选，交付真实项目试用

1. 复用既有 Node 业务、PI 运行时与 6 个 GUI 场景，按风险重组长场景，独立新增回归控制在最多 3 个，优先替换重叠项。目录、生命周期、版本和历史交互各覆盖一个最小失败例。
2. 不新增测试框架、覆盖率平台、全模型矩阵或整套截图矩阵。关键真实故障应有回归，不以减少断言数替代风险覆盖。
3. 修改时只跑受影响部分，最终候选做一次组合核对；代码或输入未变则复用证据。修复失败后只重跑受影响项。
4. Windows 用带中文和空格的真实目录走一条完整路径：配置、建作品、编辑／采纳、审读、作者定稿、导出、关闭与重新打开。
5. 确认 0.9.5 → 0.9.6 更新和免安装运行，不要求对所有旧版建升级矩阵。作者数据和已有对话在升级后可查。
6. 产物核对实际程序、Python、方法与字体资源、版本、源码提交、更新文件及 SHA-256；报告签名实际状态。
7. 交付说明给直接下载入口、首次操作和真实项目测试清单。开发检查与作者实测分别记录，不用“全部绿色”替代真实写作评价。

## 5. 交付验收门槛

| 验收项         | 通过标准                                                                                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC1 范围       | 两项目含同名书、同项目两书均不越界写；拒绝请求无混合目录登记或额外副作用                                                                                 |
| AC2 身份与兼容 | 同物理目录常见别名识别一致，敏感大小写目录保持区分；旧小说历史及旧目录级文章对话可查，私有历史不自动拷入其他文章                                         |
| AC3 任务       | preparing／queued／running 均可见并可取消；切换、新对话、重建、退出后无游离执行，旧结果不能改变新任务对象                                                |
| AC4 历史       | 旧对话只读，当前流不混入；快捷动作、命令与键盘入口一致，可返回当前对话                                                                                   |
| AC5 PI         | 隐式目录指令和设置不改变会话；既有内置工具边界保留；压缩及重试来源明确，任务方法前后一致                                                                 |
| AC6 版本       | 作者改稿后旧依据 Agent 写入被拒绝或保留为候选；当前作者版本不被悄然顶替；审读和定稿依据对应实际稿件                                                      |
| AC7 上手       | 写手与编辑就绪可见；新建及打开已有项目可操作；无 target 空态按钮有效；发送中、排队及失败有反馈                                                           |
| AC8 交付       | 当前 Windows 自动检查和一次实际使用走查通过，0.9.5 升级保留数据；程序／源码／校验清单对应，直接下载可用                                                  |
| AC9 模型适配   | 常用 API 与实际请求一致；目录与端点列表来源清楚，抓取失败可手填；带端口／代理路径可用；容量覆盖与有效思考档位一致，旧配置保留；连接检查和真实任务复用 PI |

AC1–AC7、AC9 是进入真实项目测试前的功能条件，AC8 是交付条件。模型适配优先在现有配置与 PI 场景里覆盖一个目录模型、一个自定义端点、一次模型能力切换和旧配置读取，复用第四批的真实连接走查；不做全供应商矩阵。真实模型连接和 Windows 走查缺条件时，应明确列出未执行部分及如何补齐，验收保持未完成，不把未执行写成通过。

## 6. 交付后的作者真实项目测试

先用现有备份入口保存一份原作品，再用副本完成以下三条路线；这不是新的自动测试体系。

| 路线     | 作者实际操作                                                           | 要观察的结果                                                   |
| -------- | ---------------------------------------------------------------------- | -------------------------------------------------------------- |
| 长篇主线 | 从想法规划，写两章，审读、手改、采纳、定稿和导出；中间新对话并重启一次 | 设定与前章接续、审读对象和版本、作者修改保留、重新进入后能继续 |
| 多项目   | A 任务准备／生成时浏览 B，交替发送不同要求；包含同名书或相同章节号     | 任务与结果对象明确；不串聊天、不改其他项目、每个任务能停止     |
| 头条     | 两篇不同主题分别立项、改稿、质检；其中一次作者与 Agent 并行修改        | 两篇要求独立；作者新版保持；交稿和台账对应实际文章             |
