# 0.9.3 实施记录

日期：2026-11-01（香港时间）。本提交基于 0.9.2 `ca79e68`，汇总下述两批内核实现与文档；包版本暂保持 0.9.2，不作为 0.9.3 正式发行。

本批按作者要求直接修改现有实现，只新增两个关键回归场景，不新建测试体系、数据库、调度器或通用适配框架。

| 范围 | 本批变化 |
|---|---|
| 作者确认 | PI 在作者实际同意后才批准本次确认；拒绝、取消及执行结束清理凭据；凭据绑定工具、原参数和有效期，只能消费一次 |
| 长篇敏感写入 | 工具工厂内复核定稿／force 确认；确认记录保存解析后的作品与章节版本，事务核对 expected_revision。兼容宿主的只读参数，不修改调用方对象 |
| 台账 | Python 在整个查重／更新／保存期间持有操作系统文件锁；退出自动释放；临时文件、fsync、原子替换；新记录带文章ID，重复记账复用记录，改标题后仍按身份定位；歧义旧记录拒绝自动合并 |
| PI 角色 | 编辑改为明确的审读能力白名单，保留根基／章纲读取；规划使用白名单，不能写正文或采纳正文候选；子角色不得借 status 恢复操作写入 |
| 取消与目标 | 发送前复制目标／浏览上下文；初始化或准备提示期间发生停止时不再投递任务；已取消的规则调用不启动 Python |
| 错误 | 引擎向 PI 执行层传递领域失败，保持旧 DSH 文本输出；PI 将业务失败标为工具失败，不误计成功步骤 |
| 编辑交接 | 没有当前稿件的有效审读／质检结果时明确失败，不把旧回报当成本次成果 |
| 历史 | 快照和实时事件用 PI entry ID 合并；移除全消息 stringify 去重；闲置历史按文件身份／大小／纳秒时间戳缓存，最多四份，当前会话投影按 leaf 失效 |
| 工程边界 | 现有架构守卫纳入 desktop，检查渲染层 Node／服务端越界和 PI SDK 导入边界；未做全量 JSX 类型迁移 |

## 第二批：任务上下文和有限恢复入口

本批继续使用 PI 会话与既有存储恢复，仅新增一个桌面核心回归场景。

- 编辑委派明确使用 review 意图、规划委派使用 plan 意图，避免继承主任务的写作／规划意图。审读开始时没有旧回报不会阻止任务；结束时才核验当前正文的编辑回报及当前文章／立项卡的质检结果。
- 交接摘要带入实际已保存的章节 revision、审读声明和条件依赖；头条摘要明确当前质检是否有效。正文仍由工具按需读取。
- 设置中新增当前作品状态检查。对既有章节／候选／留痕和采纳 Journal 提供确认后备份、校验、重核记录并重放的有限恢复入口；恢复前后均校验原状态，在资源锁内核对作者确认过的记录 ID 和完整文件指纹。
- 活进程、异机所有者、资源写锁、冲突和不支持的中断类型不自动恢复或删锁。备份失败／取消不重放；备份完成后若恢复失败，错误会保留备份位置。PI 模型工具只允许检查，实际恢复由作者在设置决定。
- 恢复期间阻止新任务、作者写入和作品切换；初始化或准备消息尚未完成时不开始恢复，避免同一应用内的交错写入。复用既有备份脚本，额外执行其 verify。

验证结果：公共及桌面构建通过；现有存储 19 项、桌面核心 6 项、架构守卫通过。新增场景验证首次审读、备份失败不写入、锁／冲突拒绝、实际备份及校验、成功重放和重复恢复不再应用。现有 PI 场景也验证了实际编辑消息中的 review 意图。

另执行一次 Linux 历史接口测量：两份各 10,000 个 PI entry、22,839,313 字节的会话，包含用户／助手／工具结果／作者通知。5 次无应用缓存读取为 120／102／100／102／101 ms，热读取 30 次 P95 为 0.52 ms，20 轮切换后的本进程 RSS 增量约 0.13 MiB。只测 Node 历史接口，不包含 Electron IPC、渲染、历史分支切换和 Windows；不能计作 A22 产品性能验收通过。原始记录与临时样本生成脚本保存在第二批证据目录，生成的数据已清理。

截至本批，尚待完整验证的范围主要是：全部取消／强退重启／压缩场景、跨章实际创作、Windows 端到端性能、原生界面与恢复按钮交互、完整 JSX 类型覆盖、真实模型 E 集及 Windows 交付。首批「未完成范围」是当时记录；恢复入口现已实施，但图形环境下的作者操作仍未验收。没有发布或声称整版完成。


### 第二批图形复核与追加修正

本机虽没有预设 DISPLAY，但已安装 Xorg 和 dummy 驱动。本轮用临时配置在本地 :93 启动虚拟显示，无需安装依赖，实际执行现有 3 条 Electron 场景。

首次运行发现建书时的界面竞态：后台写入期间尚未形成有效快照，useFanqie 却向外通知缺少作品的目标，导致客户端错误回到项目根。修复为只有有效作品快照才同步浏览目标，未知状态不清除当前作品。原有建书场景直接验证该行为，不新增测试套件。

修正后 3 条真实 Electron 场景通过（5.5 秒），覆盖引导、实际建书、候选定位、1440／1100／900 布局与主题、方法草稿离开保护、角色设置、独立编辑、新对话；在原设置场景补充了作品状态检查按钮和无待恢复操作时不显示恢复按钮的断言。恢复正向／拒绝的核心行为由上述新增核心场景验证，完整恢复按钮的原生确认与备份文件夹选择尚未逐项图形验收。

证据目录保留首次失败 trace、成功日志、截图及临时 Xorg 配置；虚拟显示在检查后关闭。本次结果修正了首批与本批早先“本机无法运行 GUI”的判断，但不代表 Windows 已通过。
