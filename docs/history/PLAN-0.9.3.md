日期：2026-11-01（香港时间）。状态：实施中，首批内核修复见[实施记录](0.9.3-IMPLEMENTATION.md)，整版尚未完成。

代码基线：0.9.2，`ca79e6808535d01493ffd597bc5c6ca5df18c054`。本文件是 0.9.3 的需求和范围依据；与此前多宿主路线不一致时，以本计划为准。

配套文件：[开发指导](0.9.3-DEVELOPMENT-GUIDE.md)、[验收规范](0.9.3-ACCEPTANCE.md)、[验收报告](0.9.3-ACCEPTANCE-REPORT.md)。需求 R、工作包 W、验收项 A 使用固定编号，后续实施与报告按编号追踪。

## 1. 版本目标与产品边界

作者使用我们的独立客户端，就能从题材或已有作品出发，持续进行规划、起草、独立编辑、修改和作者决策；切页、长对话、停止、网络失败、退出重开不应造成对象错位、重复写入或作品状态失真。

PI 是已经内置的 Agent 运行时，继续负责模型调用、会话持久化、工具执行循环和上下文压缩。自有写作内核负责作品事实、任务目标、角色能力、创作流程、规则校验和作者决策；Electron／React 提供工作区及操作反馈。改善这些部分的实际协作，而不是另写一份 PI。

本版范围：

- 以独立桌面客户端为产品入口，以 Windows x64 为主要交付平台；Linux 用于开发及可执行的工程检查。
- 同时保障今日头条和番茄长篇；长篇重点验证跨章、新对话和修订后的连续性。
- 保留现有方法方案、文件格式、候选／审读／定稿链和作者决定权。
- 既有 DSH 为存量代码；共享业务被修改时运行既有回归，不为其他 Agent 工具新增适配需求。

不纳入本版：MCP／MCP App、WorkBuddy／ZCode／Claude 等 Agent 工具适配；云同步、账号和多人协作；自动发布；新聊天数据库、持久任务队列或独立调度器；全仓重排；未经实测的 Python 进程池；对方法论整体重写。已有模型服务商接口继续使用，它们与 Agent 工具适配不是一项工作。

## 3. 明确需求

P0：作者数据、权限和版本正确性，必须先处理。P1：本版必须具备的连续创作与工程能力。P2：本版限定规模的性能及故障体验改善；仍须验收，不能以优先级较低为由无记录地删除。对已正确的实现补证据，不为完成任务编号而重写。

### R01 · 作者确认与版本一致性（P0）

作者看到并确认的是哪篇、哪章、哪个候选、哪个版本，实际操作就必须作用于该对象和版本。

- Agent 定稿、强制修订已定稿内容必须有本次作者授权；模型提交的 `force` 或 `confirm` 布尔值不能自授权限。
- 工具执行层缺少授权、作者拒绝／取消、确认过期、重复使用确认或等待期间版本变化时，不得启动该敏感写入。
- 作者直接在界面的采纳、采用和定稿继续验证实际已读版本；正常批准恰好产生一次业务效果。
- 已定稿正文修订保留历史，修改后按现有规则降回草稿，旧审读失效；不能把“审读通过”当作作者授权。

工作包 W1；验收 A01～A04。

### R02 · 头条台账一致性与幂等（P0）

同篇文章重复点击或重复调用不会重复记账，不同文章同时处理不会丢行，状态同步不会覆盖另一操作的新数据。

- 查重、读取、更新、保存共同处于同一规范路径的写入临界区；Agent 与作者采用路径共同遵守。
- 以稳定文章身份识别新记录，旧 CSV 兼容读取；旧记录身份不明确时提示核对，不按标题相似度自动合并。
- 采用原子替换避免半写文件；进程内互斥与多开应用时的已有作品租约各自有效。
- 不为了修台账迁移所有文章数据，旧文件和用户改动保持可恢复。

工作包 W1；验收 A05～A07。

### R03 · PI 会话与任务生命周期（P1）

作者能明确知道任务是否接收、正在进行、等待决定、已停止、失败或已完成，并可在核对保存结果后继续工作。

- 发送时冻结任务对象；浏览位置改变不改变当前任务或已排队消息的目标。未保存编辑不冒充磁盘正文。
- 首次建书归属来自实际创建结果，打开已有作品不覆盖旧聊天入口。
- 初始化、排队、模型失败、重试、压缩和子角色执行都遵循 PI 的真实生命周期；不能只看是否流式输出判断空闲。
- 停止同时传递给主会话、正在启动或运行的子会话、网络和规则脚本，以及待确认操作。已开始的原子提交可以完整收尾并如实报告，不宣称停止能撤销已落盘数据。
- 重启恢复已有会话、作品和历史入口；未完成任务供作者核对后继续，不静默重放写入或模型请求。不新增自动断点续跑服务。

工作包 W2；验收 A08～A12。

### R04 · 写手、编辑、规划协作（P1）

角色分工通过实际工具权限和明确交接成立，模型配置与独立上下文保持有效。

- 写手推进业务并委派编辑／规划；子角色不递归派生子任务。
- 编辑读取必要依据、进行诊断、提交编辑候选和回报；不采纳、不定稿、不改根基或章纲。
- 规划负责开书、根基、章纲和拆书；不直接保存正文、采纳正文候选或变更章节审读／定稿状态。按参数限制混合用途工具，不能仅靠提示词。
- 工具按能力清单装配，新增工具默认不自动进入子角色；执行时保留拒绝校验。编辑读取来源按业务需要配置，不统一禁止事实核查。
- 子任务回传真实作品／文章／章节／候选及版本；没有相应产物或产物已过期时，明确失败或待核对，不按一句“完成了”标成功。

工作包 W3；验收 A13～A15。

### R05 · 长篇上下文与连续性（P1）

作者跨章、换对话和修订后继续写作时，Agent 依然使用正确依据，而不是要求作者重述全书或相信旧聊天摘要。

- 沿用 Target／Focus／发送上下文：区分任务目标、浏览位置、实际已保存状态；任务执行时重核可能过期的依据。
- 写章使用精简简报和必要的章纲、前章正文；候选依赖、工作稿、已定稿和锁定事实分开表达。不每轮注入全书全文或整套方法库。
- 前章修订后，受影响后章／候选／审读按已有指纹和依赖规则标为待核对，不自动改写其他定稿。
- 新对话、恢复或压缩后从作品工具重读必要状态；方法方案及作者偏好以实际保存内容为准。

工作包 W4；验收 A16～A18，实际效果由 A28 验证。

### R06 · 结果、错误与作者操作反馈（P1）

作者能够区分“生成了结果”“审读通过”“已经采纳”“等待确认”和“执行失败”。

- 内部结果保留明确成功／失败、错误码、对象、版本和产物身份；显示文本不是程序判断成功的依据。
- 区分模型认证／额度／网络失败、业务版本冲突、作者取消、作品占用和待恢复状态；成功步骤、通知和结果卡不把这些情况计作完成。
- 结果卡跳到真实对应对象；失败时显示已保存结果和可执行的下一步，不笼统重跑整项任务。
- 沿用现有三栏、窄屏抽屉和未保存离开保护，不重新设计编辑器；正文与方法草稿均受到保护。

工作包 W2／W5；验收 A19～A20。

### R07 · 长会话历史与响应（P2）

长会话切换和加载旧消息不会冻结工作区，也不会丢失、重复或串入其他作品消息。

- 使用 PI 的稳定消息／entry 身份及分支语义；快照与实时事件合并不依赖整条正文 stringify。
- 保留当前首批 80 条、按需增加、旧对话查看；缓存与分页按实际会话、分支和文件变化失效，支持历史文件被截断或替换。
- 性能目标以[验收规范](0.9.3-ACCEPTANCE.md)的固定样本和环境测量；不承诺 O(1) 或未经测量的百分比收益。
- 不建立第二份聊天事实库，不以删除历史或省略真实消息达到指标。

工作包 W5；验收 A21～A22。

### R08 · 作品占用与恢复体验（P2）

作者遇到占用、异常退出或未完成写入时，能看到原因、保留数据并进入受控处理。

- 区分作品租约、资源写锁和未决 Journal；展示可确认的状态及下一步，未知时明确未知。
- 从现有设置／诊断区域进入，复用备份与 inspect/resume；只在现有恢复规则允许且作者确认后重放，不能直接“一键删锁”。
- 活进程、异机来源、不可读所有权或文件哈希冲突时禁止自动解除；保留只读查看、备份和诊断途径。
- 恢复前备份并核验；无法建立可靠备份或验证恢复前提时不执行重放。重复恢复不会重复应用写入。

工作包 W6；验收 A23～A24。

### R09 · 自有客户端工程边界与兼容（P1）

- 架构守卫覆盖桌面主进程、preload 和 renderer；PI SDK 仍集中在 pi.ts，renderer 不直接访问 Node／文件系统。
- Target／Focus／作者决定／角色／结果／IPC 边界具备类型和必要运行时校验；桌面自有渲染文件纳入检查，不能用全局 any 或关闭检查掩盖问题。
- 会话生命周期、角色工具、上下文和历史按职责收敛；内部存储与浏览器接口分开。不为文件行数或假设中的外部适配器造框架。
- 默认保持当前锁定工具链及作品格式；依赖调整逐项说明原因。旧作品、配置、方法方案、导出、备份和发布构建不回退。

工作包 W7，随各包同步实施；验收 A25～A27。

### R10 · 真实写作与交付证据（P1）

- 沿用既有 E 集：默认／原版各 7 篇头条、同书 10 章长篇，第六章前新对话；核对真实稿件、质检和独立编辑回报。
- 作者评分、连续性抽查和账单均需实际填写；未知费用为 null，未执行为未执行。
- 验收报告绑定被测提交、环境、命令、退出码、产物和未解决项；代码检查、真实效果、Windows 交付分别给结论。
- 若能取得 0.9.2 真实基线，用同配置对比；没有真实旧基线时，按本版绝对验收线判断，不宣称提升比例。

工作包 W0／W8；验收 A28 及整体交付结论。

## 4. 作者流程与完成定义

| 作者流程 | 完成后必须可观察的行为 | 需求 |
|---|---|---|
| 打开旧书或首次建书 | 正确恢复或关联会话；旧对话仍可查看 | R03／R09 |
| 规划后写章，再派编辑 | 模型与工具按角色工作，交接指向实际产物 | R04／R05 |

| 停止、失败、重启，再继续 | 保留已落盘结果，状态真实，无静默重复写入 | R02／R03／R06 |
| 连续十章，第六章换新对话，修订前章 | 必要事实和依赖可追溯，冲突回到作者决定 | R01／R05／R10 |
| 头条起草、编辑、质检、交稿并采用 | 对应稿件有效，采用绑定作者已读版本，台账唯一 | R01／R02／R04 |
| 查看长历史或处理异常写入 | 消息正确可用，异常有诊断及安全处理路径 | R07／R08 |

## 5. 实施顺序与里程碑

| 里程碑 | 工作包 | 退出条件 |
|---|---|---|
| M0 基线固定 | W0 | 列明已实现／已失败／待验证，固定关键 PI 行为与验收数据；不把资源不足记为通过 |
| M1 写入正确 | W1；W7 同步 | A01～A07 通过，旧格式兼容，版本与授权接口确定 |
| M2 运行与协作 | W2／W3；W7 同步 | A08～A15、A19 通过，停止与子任务收尾明确 |
| M3 连续创作与体验 | W4／W5／W6；W7 同步 | A16～A24 通过，真实产物和性能证据可核查 |
| M4 工程交付候选 | W7 | A25～A27 的工程部分通过，Windows 包和旧数据核对完成或明确阻塞 |
| M5 产品与发行结论 | W8 | A28、作者评分和交付条件填入报告；分别给出真实结论 |

依赖：W1 的授权／版本接口供 W2／W3 使用；W2 形成结果和生命周期契约后再集中整理 W4／W5；W6 复用既有存储恢复；W7 每阶段执行边界检查，不能留到最后一次大重构。真实模型条件可在 M0 准备，有条件即采集基线，不阻塞独立工程工作。

按作者后续指示，只补关键反例的必要验证，不机械地为每个 A 编号增加测试，不在没有新改动或失败依据时重复全量检查。

按工作包提交可评审改动，每包包含实现、相应回归和证据更新。M0 后根据实际缺口、SDK 限制和可用资源估算工期；不把第三方报告的半天／一天估计当成交付承诺，也不在未知投入人数时编造日期。

## 6. 需求变更与完成判定

需求变更同步更新本计划、工作包和对应 A 项；记录原因及受影响验收，不悄悄降低指标或删除失败样本。P0 反例未解决不得进入交付候选；P1／P2 必需项失败或受阻时，报告明确为未完成，而不是“基本完成”。

每包完成条件：对应需求有实际行为证据，相关检查通过，存量数据兼容，必要文档更新，待办和限制已入报告。全部完成仍不等于已发布；版本变更、提交、打包、签名、上传和正式发布各有独立事实，本计划本身不执行这些动作。
