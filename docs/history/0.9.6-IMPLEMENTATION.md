## 实现结果

| 需求       | 本轮实施                                                                                                                                                                                                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1 范围    | PI 工具调用在业务副作用前检查项目目录、作品和文章；覆盖 work、project 别名和创建新作入口。允许共享方法读取，不把方法 id 当文章 id。主角色及委派使用同一范围；目录身份复用 realpath，大小写仅在 Windows 归一                                                               |
| R2 对话    | 文章 id 纳入 Target、会话 key、界面范围及事件；旧目录会话作为只读历史入口，不复制进文章模型上下文。历史视图过滤实时事件，发送及快捷任务、命令入口共同限制；保留返回当前对话选项                                                                                           |
| R3 任务    | 准备记录带目标及取消代际；准备期间显示忙碌、可停止；释放、停止及模型设置重建取消过期准备。停止清除 PI 待发队列并取消父子角色。事件和视图带对话身份，任务有 id；运行列表显示排队数量；重启后的未完成对话提示先核对已保存结果                                               |
| R4 PI 配置 | 显式 noContextFiles，资源加载和会话共用内存 SettingsManager，客户端拥有压缩／重试来源；保留既有工具白名单。任务从已接受消息记录方法方案，工具使用该方案                                                                                                                   |
| R5 版本    | 头条工具贯通既有条件保存；桌面按实际读取的稿件记录版本和哈希，旧依据写入拒绝，作者新版保持。已有长篇正文直写须给 expected_revision；空章节初写使用条件依据。编辑默认审读当前工作稿，候选审读提示先采纳                                                                    |
| R6 上手    | 编辑可沿用写手连接或单独设置，保持独立上下文；设置页也可复用连接。空态按钮开启引导；未发送要求按目标留在内存，切换作品后可恢复；文章切换不会释放仍在使用的共同目录占用                                                                                                    |
| R7 验证    | 复用既有业务、PI 和 GUI 场景，只新增两个运行时回归场景；失败后定向复查，没有新增框架或供应商矩阵                                                                                                                                                                          |
| R8 模型    | 保留 PI ModelRuntime 作为执行入口；读取 PI provider／模型目录、能力、费用及 thinkingLevelMap，复用 SDK 档位判断和钳制。界面补齐 API 选择、地址与端口说明、模型列表、目录刷新和自定义 OpenAI 兼容端点抓取；支持手填和容量覆盖、显式无 Key 本地连接；旧连接仍按既有方式读取 |

模型请求仍使用 PI 的协议实现、流式处理及工具循环。新增 `pi-ai@1.4.0` 显式依赖，与现有 PI SDK 同版本，经 pi-adapter 统一接入。目录缓存复用 SDK 的 InMemoryModelsStore，应用重启后先使用随包目录；没有引入新的缓存文件格式。

自定义端点抓取仅补一个 `/models` 列表读取，不把返回的 ID 当作容量或思考能力证明。目录模型选择采用 PI 元数据；用户手动覆盖继续保留。此版本不扩张 OAuth、全云平台登录或通用模型发现平台。

旧小说会话目录优先保留读取；规范化 key 变化时，根据原 PI 记录的 cwd 和旧 key 定位原入口。文章旧目录历史只查阅。作品正文、候选、逐版稿、journal 及 Key 保存方式未重建。
