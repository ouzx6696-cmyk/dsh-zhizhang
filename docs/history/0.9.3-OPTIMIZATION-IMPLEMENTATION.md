## 阶段 1：结构拆分

| 项 | 落地 |
| --- | --- |
| C2 主进程 | `main/index.ts` 只负责启动；`main/lifecycle.ts`、`window.ts`、`runtime.ts`、`targets.ts`、`operations.ts`；`main/ipc/contract.ts` 统一定义全部通道、参数与返回值，`ipc/*.ts` 按 workspace/models/session/export/backup/updates/diagnostics 注册并校验入参 |
| C4 会话 | `session/` 拆为 manager、pi-adapter、prompt、delivery、history、editor-task、task-tracker、tools、sources、roles、types；除角色表外每个模块不超过 200 行 |
| C5 Pi 边界 | Pi SDK 只允许在 `session/pi-adapter.ts` 导入，架构守卫已收口 |
| C1 渲染层 | `renderer/state` 单一 store 取代 28 个 `useState`；`renderer/app` 只做组装（74 行）；`renderer/features/*` 按功能拆分；`useDesktopController` 398 行 |
| C6 类型 | 渲染层 `client.jsx`、`Workspace.jsx`、`SettingsPanel.jsx` 全部改为 TSX，`tsconfig.renderer.json` 启用 strict |
| C3 数据接口 | `workbench/src/adapters` 提供同一份接口：`dsh.ts`（HTTP）与 `desktop.ts`（IPC）；hooks 改用 `fanqie`/`toutiao` 命名空间，视图不再拼请求 |
| 边界 | 渲染层只能经 `renderer/state/desktop.ts` 访问预加载桥，守卫会拒绝其他直接访问 |

桌面写作台组件仍复用既有实现；长篇引擎、头条工具、门禁、方法资产和存储层未改。DSH 继续按原方式装配，并使用 HTTP 适配器。
