# 0.9.5 实施与验收

日期：2026-11-02（香港时间）。基于 0.9.4 / eabd87a，需求与依据见 [迭代计划](PLAN-0.9.5.md) 和 [运行审核](0.9.4-RUNTIME-AUDIT.md)。

## 实施结果

- R1：目标切换复用串行队列，先取得访问并持久化，再提交当前目标；失败保留旧目标，旧资源释放故障单独报告。连续切换和持久化失败由真实文件回归验证。
- R2：头条列表保留正常文章并返回损坏项的位置与错误；桌面及兼容界面展示问题。固定及已选方案错误不再切默认；会话 current 仅在 ENOENT 时使用新会话。采用成功但台账失败明确报告部分成功。
- R3：移除 humanFeel 缺项自动填模板，旧通用模板也不进入 craft cue；显式实际 cue 保留，作者旧文件不回写。
- R4：规划提示独立组装，编辑提示不再包含写手委派指令。
- R5：PI 内部调用直接执行可抛错的业务实现；兼容入口单独负责错误文本。移除 exec.failure 暗传和结果字符串猜测。采纳输入及章节保存返回值补类型。源码／段落／方法的局部离开与桌面使用同一决策；更新要求修改已保存或放弃，避免先销毁会话。头条 dirty 进入任务 Focus。任务结束由 refresh 事件统一刷新。
- R6：移除采纳成功的固定说明段，零命中的 lint 不再反复发解释；停止新写 continuity.coverageNote。实际告警和权限、版本规则保留。
- R7：去掉两项状态映射镜像，新增两项关键回归；其他问题扩充既有场景。核心 96、桌面运行时 10、GUI 6、兼容运行时 1，合计与原版一致。GUI 改为单个失败不跳过后续，编辑检查自建独立作品。CI 只在 Windows 执行完整桌面运行时，UI 改动不自动触发全部兼容链；一次准备 Python 后生成 NSIS 与 ZIP。关键 lint 规则升 error，依赖告警如实保留。架构守卫使用实际 TS 模块解析并包含 client 图边。
- R8：0.9.5 版本统一；交付附件只包含当前实施、使用、README 与校验材料。原方法资产、存储格式、既有租约和恢复保护保持。

## 检查记录

首轮桌面运行时 10/10、Python 215 项通过；核心首轮发现内部错误转换的回归，修复后受影响 Node 检查 96/96 通过。桌面严格类型和构建通过。后续原生 Windows 的 GUI、实际打包启动、Python 和哈希以同提交 Actions 记录为准。

首轮出现的错误没有通过删断言放行，而是使 engineTools 默认传播异常，DSH 注册边界显式选择文本格式。无新增测试框架、覆盖率平台或自动重试。

## 实际边界

两套原版 Python 检查继续保留整体入口，不复制上游脚本做筛选；不同 CI job 各自准备依赖，未引入跨平台缓存体系。大文件和广泛 any 本轮仅沿修改路径收敛，没有以行数拆层。Hook 依赖告警未统一关闭；视觉像素比较在 CI 仍按原策略不执行。

真实模型规划、两章接续、头条与作者评分尚未执行（本环境没有配置模型凭据），AC11 保留未执行；Windows 物理机安装与跨版本更新亦不能由打包启动替代。交付为候选构建，不把这些条件记为全部验收通过，不自动发布 GitHub 正式 Release。
