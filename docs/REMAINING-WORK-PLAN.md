# 织章：发布前剩余事项与 1.0.2 待办

> 只记录还没做完的事。当前版本、验证结果与能力范围以 [STATUS](STATUS.md) 为准，已完成的变化见 [CHANGELOG](../CHANGELOG.md)。更早的排期、授权清单和签核模板已移除，需要时查 Git 历史。

## 0. 发布前还差什么

1. **打包核对**：普通推送的 CI 不走打包路径；在候选提交上手动运行 `ci.yml` 的打包路径（或 Windows 上 `npm run verify:release`），收集 `writer-windows-packages`，用运行记录的 `head_sha` 确认构建的是预期提交，核对安装包、ZIP、随包 Python、更新文件与 SHA256SUMS（第 1 节）。
2. **Windows 真机验收**（第 2 节）。
3. **真实模型门槛**：RM02 头条续跑，或由维护者正式调整门槛（第 5 节）。
4. **维护者批准**后才推 `v*` 标签；推标签即自动发布 Latest。

T134 规则修订与 1.0.2 待办不阻塞发布。

## 1. 安装包运行时检查

正式包关闭了 Node inspect，Playwright `electron.launch` 访问主进程的方式对它不一定可用；不能为了测试重新打开 Inspect fuse。正式包检查器原生启动 EXE，经仅绑定环回地址的 Chromium 调试端口检查窗口；`NODE_OPTIONS` 注入用只在临时目录写标记的脚本验证，健康启动后标记必须不存在；`--inspect` 端口健康启动后必须未监听。打包态不采用 `WRITER_USER_DATA`，隔离用独立 Windows 账户或可恢复系统。

| --- | --- | --- |

## 2. Windows 真机验收

### 2.1 环境和样本准备

- 必测：产品实际承诺支持的 Windows x64 环境；建议 Windows 11 为主。如继续承诺 Windows 10，核对 Electron 官方要求并执行相应验收，不能静默移除支持。
- 使用普通用户、独立测试账户/可恢复系统；记录 OS、架构、缩放、区域设置、权限、磁盘及运行时版本。
- 至少覆盖中文/空格路径、非默认安装目录、默认与自定义写作根、非管理员启动。
- 升级来源分别准备 `0.9.9` 和 `1.0.0-preview.1`。旧版先创建长篇、头条、草稿、连接设置和备份，保存实际文件及正文哈希。
- 真机业务流程优先使用本地假模型。未经第 5 节批准，不因为点了连接测试或写作按钮而误用付费 API。
- 保存旧版数据的独立副本、关键文件哈希、受控草稿文本和基线截图；不要对唯一真实作品做破坏实验。

### 2.3 失败处理

- 丢稿、覆盖作者新稿、锁绕过、无法恢复、密钥泄漏、无法启动/安装：阻塞发布。
- 关键流程无法完成、错误费用统计、确认取消后半退出：阻塞发布。
- 纯样式问题由影响程度分级；关键操作不可达仍阻塞。
- 每次修复后重跑失败用例及受影响流程；运行时或安装配置改变时重跑整套安装/升级/卸载，而不是沿用旧截图。
- 退回旧程序前先对升级后的数据另做副本，保留新增内容；不能把恢复旧软件等同于允许覆盖新数据。

## 4. 1.0.2 待办

以下为原模块文档明确延期的范围，不代表已经获得产品行为或数据格式变更授权。每组按“确认需求→基线测试→设计/迁移→实现→行为回归→清理旧实现”完成。

### 4.1 运行时与数据契约，优先安排
