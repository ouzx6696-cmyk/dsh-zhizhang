# 创作与质量方法

长篇引擎的质量方法服务于本书的实际阅读效果。作者目标、节奏档位和已经成立的讲法优先，工具负责提供材料和可核记录，不把词表或字段数量变成文学裁决。

## 规划与落稿

规划要交代关键经历、人物当场可接触的证据、认知边界和转向依据，让写手知道为什么能这样行动。对白、措辞与微动作仍留给正文创作。

本章可以兑现信息、关系、行动后果，也可以让安静体验成立。不强制每章添加反派、代价、反转、固定场数或钩子。快爽的经验数字不自动约束稳推和慢燃，平台规则需使用当期可核来源。

参考迁移的是机制与成立条件；本书需要重新建立人物所求、能力限制、筹码和事件链。合理回应取决于人物当场已知，不等于每场必须加入敌人。

## 审读与编辑

先完整读正文及必要依据，再定位问题，说明位置、证据、阅读影响和最小修改方向。主要核对：关键经历与落点、本书约束、人物认知来源、正文接续。

| 修改层级 | 关注点 |
| --- | --- |
| L1 结构与单元 | 事件是否成立，推进与结果是否有依据 |
| L2 场面与交锋 | 人物如何行动、回应，关系或信息如何实际变化 |
| L3 句面与声音 | 语言是否准确、自然，是否符合本书讲法 |

依据真实损失选择层级。只获准润色时不偷改路线；获准重构时处理因果和场面，不只替换词语。改后完整回读，并复核原有约束和接续。

直接心理、长句、市井口气、热烈反应、必要说明和完整收束都可能有效。机械命中提示回看，默认不硬拒；显式 strict 策略属于用户选择。

## 证据能证明到哪里

| 工程证据 | 可以证明 | 不能证明 |
| --- | --- | --- |
| 引文命中 | 指定材料中有这些字句 | 解释正确、技法有效、读者喜欢 |
| 阅读申报 | 调用方声明读到的范围和程度 | 真实阅读已被独立核验 |
| 扫描凭据 | 对指定版本执行过机械检测 | 内容审读通过或有文学价值 |
| 审读记录 | 指定主体对版本和依据作过结论声明 | 作者授权、市场效果或无遗漏 |
| 覆盖和完整度 | 已处理材料及字段范围 | 分析正确率 |

客户端不自动投稿或修改 AI 标识，不把教学例稿当作市场证据。操作上的审读、采纳和定稿见[作品生命周期](COGNITION.md)，具体编辑约定见[作品编辑与修订](skills/web-novel-master-optimizer.md)（运行时用 `fanqie_method_get ids=edit` 取当前方案的 edit 方法）。

## 追读工程：离线标尺（P0）

`scripts/fanqie-corpus.mjs` 复用拆书库的章节解析，调用现有 Python `scan_style`，不复制雷达规则，不改 strict 策略、方法原文或默认写作行为。此阶段提供统计与现有雷达基线，尚不调整检测阈值。

先 `npm run build`，再运行（原文、清单和输出均放在仓库外）：

```bash
npm run --silent corpus:fanqie -- --manifest /workspace/corpus/input.json > /workspace/corpus/baseline.json
```

清单示例（file 相对于清单所在目录；id 是自选标识）：

```json
{
  "books": [
    { "id": "human-01", "kind": "human", "file": "human-01.txt" },
    { "id": "ai-01", "kind": "ai", "file": "ai-01.txt" }
  ]
}
```

输入为 UTF-8 整书 TXT，以现有解析器支持的“第N章”标题分章。默认按文件顺序取前 30 个正文章节；`--limit` 可调整，不计序章。重号、空章、无法识别目录均报错，不把它们当成通过样本；非连续的第 1–30 章或不足 30 章标为样本不完整。正文内以章节标题开头的行会被识别为目录，请先整理书源。作者话、番外及占位章需在本地先行剔除，不靠猜测自动删除正文。

输出固定以下口径，并保存整本书源及雷达代码 SHA-256，便于复核：

- 字数按 Unicode 码点，去空白、章节标题和独立分隔行，保留标点。独立的省略号、横线等分隔行单独计数，不算末段。
- 段落按非空物理行，短段为 ≤30 字，长段分别计 >80、>120 字；输出章长和段长的均值、p10/p50/p90（线性插值）。这与当前流水线按空行分段的 readability 描述值有区别，P0 不改变旧行为。
- 对白占比为现有雷达识别的配对引号并集内非空字符（去外层引号）/正文非空字符，支持中文、直引号和直角引号；不是“引号开头段落”的占比。引号内的引用也会计入，不能自动证明是人物对白。
- 雷达触发率只计算叙述命中，台词命中另计；每千字雷达密度按章输出。另记录固定虚词及书面连接词的每万字密度（此项包含对白），不新增拒收规则。
- JSON 只输出数字、固定指标、来源 ID 和指纹，不输出正文、引文、上下文或本机路径。不要把自选 ID 写成敏感内容。

`evaluation` 分别汇总 human/ai 章节触发率及差值，并单列真书触发率是否 <10%。缺任一组或样本不完整时为 `insufficient-data`；两组齐备也仅为 `baseline-only`。真书“至少命中一次”是误报代理，不是逐条人工标注的误报率；AI 与真书的差值没有自动达标结论。七本榜单原文必须各自提供，脚本不凭书名判真，也不把重复语料当成独立证据。使用可比题材、章长和抽样方式，并人工核对后再决定 P3 的阈值与区分度标准。现阶段不添加会假通过的 CI 质量门禁；CLI 行为回归沿用现有 Node 测试与 CI。

## 追读工程：规划与定稿账本（P1）

实验入口为应用 userData 下 `writer.json` 的 `fanqie.pursuit.enabled`（默认关闭）。合并该字段并保留已有配置，重启应用生效；目前没有新增设置界面。示例：`{"fanqie":{"pursuit":{"enabled":true}}}`。这些机制尚未做真实模型质量 A/B，不能据软件回归宣称追读率提升。

开启后，规划流水线在根基与滚动章纲之间生成当前和下一单元，每个单元包含全书起止章序、核心问题、兑现清单、结算与下一单元伏笔。交付仍等待作者采用；采用后写入现有 `meta.json` 的 `planning.units`，保留既有卷幕规划，并沿用规划备份、版本检查及重入保护。单元范围与章纲的 `unit/unitPos` 必须一致。

章纲增加可选字段 `function`、`unit`、`unitPos`、`hookType`、`payoffType`、`newTerms`、`newCharacters`、`threadsOpen/threadsClose`、`pressure`。开启实验的滚动规划要求这些字段（无兑现可不填 payoffType）；旧作品不自动补数值，作者完整章纲不因缺少新字段被强制重写。补全章纲时保护作者已有追读字段。工具、章纲存储与流水线共用字段校验；章纲的计划不充当正文兑现证据。

`pressure` 为显式填写的连续受压章数，0 表示本章未受压。现有连续性面板巡检已接入这个字段；旧作品缺失字段时不推断受压。巡检仍沿用原有快爽档上限，不调整方法阈值。

定稿记账在原有 `writer-continuity.json` 章节记录中保存有原文引文的兑现、名词引入/使用、人物登场/标签复现/第二面、短中长悬念开合与建议到期章序。已有事实冲突确认机制不变。四本账由章节记录按实际章序汇总，不另存累加计数器；重跑替换同章记录，旧版同正文记录也可补齐。缺失记账会显示覆盖不足，不能解释成没有兑现。

后续规划和写章材料包含：兑现日历及当前单元兑现数、近10章钩子及连续同类计数、悬念在挂数与到期、设定及人物提醒。悬念、名词、人物各最多展示30项，并报告总数和省略数；完整记录仍在本地。正文、章纲或章序变更后，版本不匹配的记录不进入新材料；无法读取关联章节时报错。十章体检的建议保存在连续性状态，限定供后5章参考；来源章失效或已跟踪账本有失效记录时不注入建议。模型建议不升级成已确认事实或硬性拒收条件。

本阶段未改方法原文、语感雷达阈值、写手卡或开篇规格。P2 继续处理写手材料；P3 的阈值校准仍需要可复核的真书和 AI 稿。

## 预览版的 P2、P3 与对标书入口

“设置 › 写作引擎”现在提供“追读规划与写手材料”和“阅读量化提醒”两个独立开关，默认均关；无需手工改 writer.json。开启追读规划后，写手规则卡组合 write-chapter、prose、rhythm、章内节拍、开篇规格及四账摘要，总长上限2500字，超限报错；完整账本仍作为预算内材料提供。前章为末1500字加同正文指纹的摘要。读者画像补充具体偏好与期待、变化、兑现、接续、追读等维度。默认 edit 方法统一为：违反作者锁定且造成实际影响才列硬伤，未锁定章纲偏离只列建议。

量化提醒开启后，读者比较、审读和交付报告可看到同一口径的统计及警告。章长、段形、对白占比、长段、章末、开头回顾标记、固定虚词重复及账本到期均只作回看提示，不自动成为审读硬伤。使用对标书时，参考区间来自样本p10–p90，固定虚词密度参考样本p90；这是用户选择的描述性参照，尚非通过真书/AI对照验证的分类阈值。没有对标书时不编造密度阈值，原雷达照旧。有对标书并启用提醒时，采纳扫描与候选/章节诊断一致使用密度模式；纯文本诊断不带作品参照。strict_lint 仍是作者显式选择，词表之外的真实问题仍由审读处理。

追读实验模式下，书感不再使用特定测试书的仪式母题和“没有债务关键词”推断，账务/家务流水检测停用，通用短语复用及明确收束检查保留。兑付词表优先使用作者给定词表或本章 newTerms/newCharacters，不自动套用默认测试书器物。

“设置 › 资源与备份”可把已导入小说设为当前长篇的对标书，统计前30个有效章节并保存来源指纹、样本数、区间和密度，不保存或上传原文到本书设定。可手工确认首章异常比例、独有办法露出章、首次兑现章作为开篇参考，也可清除对标恢复默认。源文件缺章、重号或空章会要求先整理；不足30章可计算但会展示实际样本数，小样本不代表稳定风格。语义时点不能由脚本可靠判断，界面不会冒充自动测量。

P0/P3 语料验收仍缺原文及AI稿；P4按维护者选择跳过。上述功能保持实验开关，不把软件回归等同于质量提升或市场证据。当前预览版不需要付费模型即可开发、运行本地假模型回归及GUI旅程。
