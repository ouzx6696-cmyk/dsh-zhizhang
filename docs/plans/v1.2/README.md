## 实施顺序

每一批单独保持可编译、可运行、可验证，不并行铺开包化、流水线和 UI 全仓迁移。

### M1：作者操作与运行时一致性

1. 先复现并发抽卡的停止缺口，明确父会话拥有多个子会话时的注册、释放、中止和退出语义。
2. 明确所有 IPC 调用的成功/失败传输契约，保留错误码、现有返回值和调用方取消语义；先从少量真实错误通道贯通。
3. 按请求目标解析登记目录和实际锁根；核对只读打开、跨作品写入、目录初始化与切换失败。路径由现行目录登记和选择流程授权，不简单删除当前合法的 root 参数。
4. 连续性 commit 复用现有 journal 基础设施，使多文件写入可整体完成或经现有恢复入口接续；统一锁归属，避免重复读改写和嵌套锁设计。

验收覆盖具体故障和作者可观察结果，不为每个通道复制整套大流程。结束时跑一次完整本地验收；Linux/Windows CI 跑实际平台路径。

### M2：版本语义与短进程协议

- 先列出审读、候选、编辑器、定稿、流水线和恢复各自比较什么，再确定内容身份与操作状态版本的契约。内容身份可评估纳入标题；状态不混入审读身份。状态版本可采用确定性哈希，只有确需单调序号时才新增持久字段。
- 检查跨进程 stdin JSON、大参数与 POSIX 子进程树超时清理；保持短生命周期。涉及 `skill/` Python 原文改动时，先明确其规则或执行协议影响及资产清单更新范围。
- 核对 `s4-news` 的实际方法依赖及当前注入顺序，建立确定性内容/顺序检查；缓存收益须由真实服务商数据证明。

### M3：基于测量的业务整理

- 按用例调整 `ports`/`storage`/`services` 归属，复用已存在的通用 journal；不为减少文件数合并无关事务。
- 流水线材料与输入指纹共用明确依赖投影；保留最终锁内核对和自身副作用恢复。
- 局部 edits、全文兜底、经济档裁剪和 Top-2 选稿分别做小步验证。保留现有两轮编辑规则；假模型仅验证编排，不能证明质量或付费 token 改善。
- 备份执行入口与 Fuse 作为一组改动，覆盖真实打包产物启动、备份、取消、退出及更新链。

### M4：包边界与前端迁移

- 先在一个小包验证导出、浏览器安全边界、测试、electron-vite、资源复制及正式包依赖，再决定是否全面采用 workspace 包名与 project references。
- TSX 和异步响应守卫按功能迁移，替换完成再删除旧实现。CSS 业务变量与设计 token 先按用途核对，不按前缀批量删除。
- 测试按职责整理；文件数量、框架名称和净减行数不作为成果指标。Windows 保留文件、锁、Python、桌面与 GUI 覆盖。

## M1 开发记录

- 子会话从一对一映射改为集合，返回独立的释放函数；结束一条并发分支不会注销另一条分支，停止及退出清理覆盖所有注册子会话。
- 所有主进程 handler 返回统一回执；preload 只传输回执，渲染端重建 Error。现有桌面方法的成功返回值不变，错误保留 name、message 和字符串 code。真实 Electron GUI 旅程增加一次过期锁接管失败检查，验证错误码跨过两道边界。
- 命令目标按登记项目、已知头条目录及物理路径解析。写请求核对实际目标锁，不依赖界面缓存的只读标志；拒绝未登记 root 和 root/项目不一致。只读选择仅登记本机选择，不初始化共享作品目录；只读诊断走读取计算，保存修订仍在锁内核对依据。
- 连续性事务使用 `.writer-chapter-pending.json`，按需写入伏笔并统一提交章节交接、提交记录；复用现有检查、指纹确认、备份与恢复。存储读取遇到未完成事务会要求恢复。移除已无生产引用的单文件交接/提交写入函数。
- 新增中断、作者改动冲突、恢复及并发版本检查回归；既有 T115 按新的事务恢复流程验收，恢复后的重复提交继续保持幂等。未新增运行时依赖，未改写作规则或方法原文。

## M2–M4 完成记录

### M2：版本、参数传输与方法依据

| 用途 | 当前契约 |
| --- | --- |
| 审读、候选、定稿和连续性引用 | 内容 `revision` 绑定标题、正文、章纲、顺序；状态变更不改变它。改标题会使旧审读失效 |
| 作者编辑、审读声明与定稿操作 | 复用 `readVersion`，保存时用 `expectedReadVersion` 核对状态和审读记录；不增加持久化版本计数 |
| 候选列表与外部修改 | 保留原 `readVersion` 和正文文件检查，不另建索引真源 |
| 工作流继续与恢复 | 比较实际稳定材料、阶段材料、目录身份、作者偏好和方法指纹；最终写入仍在锁内核对 |

Python 短进程的参数通过 stdin JSON 传输，由轻量入口还原规则脚本参数；未改动 `skill/` 原文。大文本不再受命令行长度限制。POSIX 超时与取消终止整个进程组，保留 TERM 到 KILL 的两秒收尾；Windows 继续使用进程树终止。

资讯方法依赖按 `s4-common → s4-news` 注入，公共规则和本阶段规则各一次，两者都参与缓存与工作流指纹。handoff v2 的方法全文块放在动态上下文之前，解析与去重同步调整；未宣称真实服务商缓存或费用收益。

### M3：写作流程与数据职责

- 多稿先按四项读者维度初选，再对前两名进行画像与交换位置比较。八稿高档选稿部分由 70 次比较改为 1 次初选加 10 次位置比较；本地假模型验证了 11 次调用，不包含起稿、方法准备和编辑调用。
- 硬伤修订、事实修订与质检精修支持唯一原文引用的局部替换；重复引用、重叠补丁会报明具体问题。全文返回仍是显式可用方式；原段落范围、篇幅变化约束和两轮编辑上限保留。
- 经济档直接使用已核对章纲或立项卡准备结构，省去额外场景/蓝图模型调用；事实链、编辑和现有 Python 质检仍执行。
- 长篇材料和输入指纹使用同一投影，未引用的后章正文变化不打断当前章；当前章、前章、所见目录状态和实际材料变化仍阻断。保留自身交付识别和锁内最终核对。
- 拆书分析用例从 `ports/analysis` 移至 `services/analysis`。策略门禁仍在 ports，存储日志仍在 storage；未为减少文件数合并无关事务。
- 备份使用 Electron utility process；退出取消后台备份，完成后仍进行清单与正文校验。RunAsNode 关闭，资源复制与恢复入口沿用现有实现。

### M4：包与界面边界

- `@writer/ui` 作为本地 workspace 包，声明浏览器组件、文案、状态和样式子路径；主进程使用的文案在构建时打入包内，不留下生产态 TypeScript 依赖。
- UI 基础组件、Markdown、共享写作区控件转换为 TSX，基础属性使用明确类型；未新增 any 或非空断言。
- 方法方案的列表、详情和方法全文共用请求守卫，旧请求、切换方案和卸载后的回执不得覆盖当前内容；异步离开确认后再次核对请求身份。
- 依赖守卫识别 workspace 导入，并检查 UI 不得访问 Node。版本守卫同时核对新包版本。测试继续使用 node:test 和既有共享准备流程。

### 已作出的范围决定

包试点已覆盖类型、生产构建、浏览器依赖和资源路径。当前保留其余业务 JSX 与现有编译入口，不铺开所有业务包的 package exports/project references；本地核心编译约六秒，现阶段没有足以支撑全面工具链替换的收益证据。也不引入通用 DAG、常驻 Python worker、额外测试框架或候选索引真源。CSS 业务变量保留其语义，不按前缀机械删除。

这些是本轮已完成评估后的实现取舍，不作为待补齐的隐藏清单。上传原文中的性能比例、删行指标与工具数量目标不属于交付承诺。写作规则和方法资产原文未改动，未调用付费真实模型。
