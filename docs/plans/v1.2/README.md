## 实施顺序

每一批单独保持可编译、可运行、可验证，不并行铺开包化、流水线和 UI 全仓迁移。

### M1：作者操作与运行时一致性

1. 先复现并发抽卡的停止缺口，明确父会话拥有多个子会话时的注册、释放、中止和退出语义。
2. 明确所有 IPC 调用的成功/失败传输契约，保留错误码、现有返回值和调用方取消语义；先从少量真实错误通道贯通。
3. 按请求目标解析登记目录和实际锁根；核对只读打开、跨作品写入、目录初始化与切换失败。路径由现行目录登记和选择流程授权，不简单删除当前合法的 root 参数。
4. 连续性 commit 复用现有 journal 基础设施，使多文件写入可整体完成或经现有恢复入口接续；统一锁归属，避免重复读改写和嵌套锁设计。

验收覆盖具体故障和作者可观察结果，不为每个通道复制整套大流程。结束时跑一次完整本地验收；Linux/Windows CI 跑实际平台路径。

### M2：版本语义与短进程协议

- 先列出审读、候选、编辑器、定稿、流水线和恢复各自比较什么，再确定内容身份与操作状态版本的契约。内容身份可评估纳入标题；状态不混入审读身份。状态版本可采用确定性哈希，只有确需单调序号时才新增持久字段。
- 检查跨进程 stdin JSON、大参数与 POSIX 子进程树超时清理；保持短生命周期。涉及 `skill/` Python 原文改动时，先明确其规则或执行协议影响及资产清单更新范围。
- 核对 `s4-news` 的实际方法依赖及当前注入顺序，建立确定性内容/顺序检查；缓存收益须由真实服务商数据证明。

### M3：基于测量的业务整理

- 按用例调整 `ports`/`storage`/`services` 归属，复用已存在的通用 journal；不为减少文件数合并无关事务。
- 流水线材料与输入指纹共用明确依赖投影；保留最终锁内核对和自身副作用恢复。
- 局部 edits、全文兜底、经济档裁剪和 Top-2 选稿分别做小步验证。保留现有两轮编辑规则；假模型仅验证编排，不能证明质量或付费 token 改善。
- 备份执行入口与 Fuse 作为一组改动，覆盖真实打包产物启动、备份、取消、退出及更新链。

### M4：包边界与前端迁移

- 先在一个小包验证导出、浏览器安全边界、测试、electron-vite、资源复制及正式包依赖，再决定是否全面采用 workspace 包名与 project references。
- TSX 和异步响应守卫按功能迁移，替换完成再删除旧实现。CSS 业务变量与设计 token 先按用途核对，不按前缀批量删除。
- 测试按职责整理；文件数量、框架名称和净减行数不作为成果指标。Windows 保留文件、锁、Python、桌面与 GUI 覆盖。

## M1 开发记录

- 子会话从一对一映射改为集合，返回独立的释放函数；结束一条并发分支不会注销另一条分支，停止及退出清理覆盖所有注册子会话。
- 所有主进程 handler 返回统一回执；preload 只传输回执，渲染端重建 Error。现有桌面方法的成功返回值不变，错误保留 name、message 和字符串 code。真实 Electron GUI 旅程增加一次过期锁接管失败检查，验证错误码跨过两道边界。
- 命令目标按登记项目、已知头条目录及物理路径解析。写请求核对实际目标锁，不依赖界面缓存的只读标志；拒绝未登记 root 和 root/项目不一致。只读选择仅登记本机选择，不初始化共享作品目录；只读诊断走读取计算，保存修订仍在锁内核对依据。
- 连续性事务使用 `.writer-chapter-pending.json`，按需写入伏笔并统一提交章节交接、提交记录；复用现有检查、指纹确认、备份与恢复。存储读取遇到未完成事务会要求恢复。移除已无生产引用的单文件交接/提交写入函数。
- 新增中断、作者改动冲突、恢复及并发版本检查回归；既有 T115 按新的事务恢复流程验收，恢复后的重复提交继续保持幂等。未新增运行时依赖，未改写作规则或方法原文。
