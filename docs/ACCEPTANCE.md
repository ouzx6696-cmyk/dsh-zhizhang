# 自动化验收

软件验收使用本地假模型和确定性的业务回归，不调用真实模型 API，不要求人工打分、盲评或连续多日冒烟。

## 日常检查

- `npm run verify`：类型、lint、架构、格式、导出、Python 与 Node 业务回归。
- `npm run verify:desktop`：桌面构建、PI 与本地假模型、完整 GUI 旅程。
- `npm run test:all`：发行前运行上述两组检查。Linux GUI 需先启动显示服务并设置 `CI=1 DISPLAY=:99`。
- `npm run assets -- check`：核对资产清单与磁盘一致。

本轮新增 `test/desktop/workflow.test.mjs` 两条完整场景，直接经过生产 `Sessions.workflows` 与 PI 本地假模型，文章质检调用真实 Python 规则；原有 GUI 旅程补充设置取消和流水线入口。

每个场景核对完整行为和失败恢复，不逐句拆测试；子进程失败或被信号终止即失败，跳过不计通过。假模型覆盖工具调用、错误与取消、作者确认、候选与审读、保存和恢复，GUI 通过真实作品菜单完成编辑与保存。

## 云端与发行

推送后等待当前提交的 CI 完成；出现错误须修复并重新运行。Windows CI 执行原生桌面测试，构建 NSIS 安装包和 ZIP，检查随包 Python、应用启动与更新清单，再生成校验文件。发行工作流依赖这些检查成功后上传附件。

应用中的模型调用、连接测试和作者对稿件的决定属于产品功能，不是软件发布的人工测评门槛。
