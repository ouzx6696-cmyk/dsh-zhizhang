# 0.9.1 实施与交付记录

日期：2026-10-31（香港时间）。独立客户端为开发预览；发行附件与说明见 [v0.9.1](https://github.com/ouzx6696-cmyk/dsh-zhizhang/releases/tag/v0.9.1)。

## 本版目的

落实 [0.9.1 优化意见](0.9.1-OPTIMIZATION.md)，让独立入口围绕作品连续工作。沿用现有业务、方法资产、门禁和文件格式；Pi 继续负责会话、排队、压缩与取消。

## 已实现

| 范围 | 实际变化 | 原因 |
| --- | --- | --- |
| 任务对象 | 页面提供文章、章节、正文或候选及已加载版本；发送时与指令一起固定下来 | 浏览位置与运行任务需要分开，切页不应改变已经发送的工作 |
| 长项目交接 | 每次发送带入当前方法方案与少量已保存状态；正文与规划继续通过原工具读取 | 恢复和压缩后仍依靠作品事实，不复制全书或另建记忆系统 |
| 发送接收 | 使用 Pi 的接收回调，区分准备失败、开始运行和进入队列；准备失败保留输入 | 不能把尚未准备成功的任务报为已发送 |
| 新书关联 | 建书工具提供实际创建结果，只有这类结果可以延续根目录对话；已有会话标记保留 | 页面选中已有作品不能触发会话迁移 |
| 作者操作 | 内存中有关联会话时，以 SDK 不触发模型的自定义消息记录简短操作；去掉 nextTurn 延迟队列 | 作者操作记录应进入会话历史，避免下一次发送前退出就丢失通知 |
| 两种入口 | 头条桌面按钮不再检查 DSH 会话登记；编辑调用说明按入口装配，桌面按钮不追加 DSH 启用提示 | 独立版不需要模拟宿主；DSH 默认装配保留 |
| 编辑结果 | 编辑接收明确的作品、章节或文章；返回既有审读回报或质检有效性摘要，并可打开对应位置 | 运行结束、文字结论、作品中的实际回报需要区分 |
| 任务反馈 | 正文流与工具进度分开，工具详情折叠，空助手消息不显示；保留错误文本和结果原文 | 作者需要看到工作结果，详细调用信息可按需展开 |
| 运行与停止 | 用 SDK 完整空闲状态提供恢复状态；显示其他作品的运行提示，支持返回和停止 | 压缩等阶段也属于任务运行，后台工作需要可发现 |
| 布局与历史 | 宽窗口为对话留位，窄窗口使用抽屉；最近 80 条记录先显示，更早记录按需加载 | 减少遮挡与初始传输、渲染负担 |
| 阅读恢复 | 保留同一作品上次的阅读位置；保存模型设置后刷新按钮能力 | 重启后接着工作，设置生效不依赖手动切换项目 |

没有引入任务数据库、额外服务进程、跨宿主消息框架、第二份聊天存储或新的测试体系。共享业务的变动限于宿主提示装配、按钮文本及明确的建书结果回传。

## 使用流程

打开创作目录并保存模型连接后，可以直接从写作台按钮开始工作，也可以在对话里提出要求。对话会显示当前阅读对象；任务运行时另行显示本次任务对象。正在编辑但尚未保存的段落仍留在页面，Agent 使用已保存稿件。

新建作品后，对话可以随实际建书结果归入该作品。切换已有作品恢复它自己的对话。编辑结果可以展开查看原文，或跳回相应章节、文章；作者仍在原写作台完成采用、采纳和定稿。

历史读取不依赖模型连接。“刷新对话”重读当前会话；“查看更早消息”扩大展示范围。SDK 的历史文件与压缩记录仍是唯一聊天存储。

## 边界与未验证项

- 当前环境为 Linux，未运行 Windows 桌面，也未使用真实模型完成创作流程。构建结果不代替这些运行结论。
- 本版 Windows 交付使用免安装 ZIP。NSIS 安装器沿用已有构建入口，本轮未重新尝试 Linux 缺少 Wine 的路径。
- 历史初始传输与渲染有范围限制；SDK 底层仍读取其会话文件和分支，未声称实现磁盘增量读取。
- 后台提示来自当前进程中的 SDK 会话；退出后保留对话与作品，不自动重启未完成任务。
- 没有已打开的关联会话时，页面操作不为通知而启动模型；实际结果保存在作品中，后续任务按当前状态重新读取。
- 排队消息携带发送时的对象、方法方案与状态线索；真正读写仍须由原工具核对当前正文与版本。
- 停止不撤销已经完成的保存；独立版与 DSH 同时写同一作品仍不在支持范围。
