# 写作 Agent 架构

`dsh-writer` 是 DSH 插件。DSH 负责模型对话、工具运行和会话；插件负责头条和小说的业务规则、任务、稿件与工作台。两种模式按会话隔离，默认入口分别是 `toutiao_enable` 和 `fanqie_enable`。

## 边界

- `packages/dsh-adapter` 对接 DSH 的作用域工具、提示段落、门禁、结果事件、HTTP 路由和会话投递。番茄入口使用作用域 ToolRuntime 启用内部小说工具；兼容入口可在配置中开启。
- `packages/toutiao` 保存文章、版本、立项、QA、交稿单和台账。`packages/fanqie` 提供小说方法、章纲检查及版本化编辑回报。
- `packages/zhizhang` 维护作品、设定、章节、候选、审读声明、定稿与恢复日志；它是内部模块，沿用旧作品目录。
- `packages/app` 的任务层绑定项目、作品、章节和会话，按已存产物推导下一步。任务不调用模型，也不代替业务工具的作者确认。
- 工作台使用 `/writer`、`/writer/action`、`/writer/toutiao` 和 `/api/dsh-zhizhang/*`。任务与头条页面仅接受本机且 Host/Origin 可信的访问；小说 API 沿用自身的本机或受控局域网策略。

## 任务与数据

任务记录在项目 `.writer/tasks/`；头条稿和小说作品仍分别存在原业务目录。任务保存标识和审读状态，小说写作包只汇集当前章、前两章以及关联规划与连续性；更早资料可通过原工具按需读取。

新文章和新作品先预留标识。任务恢复以实际稿件、候选、回报和版本为依据；目录不完整或候选损坏时明确报错。任务修改复用文件锁，多会话接管后，旧会话不能继续写入该任务。模型请求超时或投递结果不明时，不假定模型没有运行。

小说编辑只可查询、审读及创建编辑候选。开启 `fanqie.requireEditorPass` 时，定稿要求独立编辑对当前正文的完整通过回报。章节本身的审读声明、依赖版本和作者确认仍由小说引擎检查。

## 验证与历史

`pnpm check` 编译一次，运行架构检查、业务测试、小说引擎测试与长篇桥检查；设置 `WRITER_DSH_RUNTIME` 后同一命令还会运行真实 DSH 组件测试。`pnpm test:host` 是可选的两种模式宿主验收，使用模拟模型，不代表真人写作质量。

旧版设计草案和开发计划保存在 [history](history/)，版本交付记录见 [releases](releases/)。
