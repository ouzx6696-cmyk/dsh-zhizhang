# 织章 1.0.0-preview.1 优化报告

- 日期：2026-11-08
- 基线：`origin/master` 643eb10（T22：可恢复写作流水线），tag `v1.0.0-preview.1`
- 改动：19 个文件，约 +700 / −170 行，其中新增 1 个源文件（`apps/desktop/src/workflow/article-facts.ts`）。
- 未做：真实模型验收（遵守余额约束，一次真实 API 都没调用）；Windows 安装包与 Electron GUI 旅程（沙箱缺 GTK 库，`libatk-1.0.so.0`，属于环境问题，与本次改动无关）。

## 一、结论

T22 已经把 1.0 报告里的“编排归代码”落了地：阶段流水线、上下文包、阶段卡、读者比较、交付回执都有了。这次没有推倒重来，改的是**会让真实写作跑不完、跑偏或白花钱**的地方。按影响从大到小：

1. **默认预算跑不完标准档黄金章**，任务会在中途暂停。
2. **长书越写越大**：每章的必带材料随章数增长，写到几十上百章时，每个阶段都会报“阶段上下文超预算”。
3. **模型输出稍有不规范，整单失败**：要求模型逐字回显 64 位哈希；正文 JSON 里的裸换行解析不了；引文差一个空格或引号就算不在原文里。
4. **修了两轮还有硬伤就把整次结果扔掉**，钱花了，作者却什么也拿不到。
5. **头条用的是番茄读者**（“追更读者”）给稿子投票。
6. **读者每投一票都附整本书材料**，这是最大的无效 token 开销。
7. 其余：多稿串行太慢、标题撞车要等到最后才报、事实链发现无来源事实只能失败、系统代理把本地模型也代理出去。

## 二、逐项说明

### 1. 任务预算（`packages/core/src/workflow-config.ts`、`EngineTab.tsx`）

**问题**：`runBudget` 默认 200000。粗算标准档第 1–3 章：5 稿，加 4 个挑战者 × 3 位读者 × 2 个位置 = 24 次比较，每次约 1.2–1.5 万输入 token，比较环节就要 30 万以上。所以默认设置下黄金三章必然在中途撞线暂停。

**改动**：
- 默认值改为 1200000，上限从 1000000 提到 20000000，阶段预算上限不变。
- 已保存的旧默认值 200000 读取时自动升级为新默认；作者自己改过的其他值保持不变。
- 设置页的输入范围改为读同一份常量，界面和校验用同一个来源。

### 2. 上下文随章节规模增长，不随整本书增长（`workflow/context.ts`）

**问题**：每个阶段的“本章与来源材料”是一整块必带内容，里面有完整根基（`happened` 每次定稿都会变长）、整本书的规划、全部章节目录、所有“兑现章 ≤ 当前章”的伏笔（已兑现的也算）。必带内容超过阶段预算就直接抛错，长书写到一定章数后每章都会失败。另外，锁定、人物、文风在“本书设定”和材料里各出现一次。

**改动**：材料拆成有序的块，必带块不截断，可选块按预算让位。

| 块 | 必带 | 规则 |
|---|---|---|
| 本章 | 是 | 当前章节对象 |
| 前章结尾 | 是 | 前章标题 + 末 800 字 |
| 到期伏笔与知情边界 | 是 | 只发未兑现、且 3 章内到期或本章有笔的伏笔线 |
| 已确认事实 | 是 | 只发本章章纲提到的主体 |
| 本卷规划 | 否 | 只发包含本章的卷和幕，每项最多 4000 字 |
| 全书规划 | 否 | 前 2000 字（规划本书时 12000 字） |
| 近期章节记录 | 否 | 最近 3 章 |
| 根基 | 否 | 已发生、读者已知、伏笔取末尾 3000 字，计划取开头 3000 字；锁定、人物、文风不再重复 |
| 章节目录 | 否 | 总数 + 最近 20 章（规划本书时给全部） |

头条：作者反馈文件会一直累积，现在只带最近 4000 字；文章与立项卡、当前工作稿分成两块。

记账（`continuity.ts`）：提取阶段只带本章正文和正文里出现过的主体的旧事实，不再带全部账本，也不再重复附一份章节材料；十章体检只读最近 150 条事实和最近 30 章摘要。

### 3. 缓存友好的阶段包顺序（`workflow/run.ts`）

**问题**：原来第一块“阶段职责”里拼了每个阶段各不相同的返回格式，所以不同阶段之间没有可共享的缓存前缀。

**改动**：顺序改为“职责（固定文字）→ 本书设定 → 材料 → 本阶段方法 → 本阶段输入 → 作者要求 → 返回格式”。同一任务的所有阶段共享前三段，DeepSeek 这类按前缀计费缓存的服务能吃到缓存价。`model()` 新增可选参数 `{ material, retries }`，阶段可以换成更轻的材料或增加重试次数。

### 4. 读者比较：省 token、分模式、并行（`workflow/editor.ts`）

- **轻材料**：番茄每票只带本章章纲和前章结尾，头条每票只带立项卡，不再附整本书材料。读者只需要判断“愿不愿意读下去”，用不到根基和目录。这是本次最大的 token 节省，按估算每票少 30%–60%，未实测。
- **头条读者画像**：标准档是“四五十岁的资讯读者、关心身边事的普通读者、挑剔的老读者”，精品档再加“城市上班族、重视事实可信度的读者”。番茄画像不变。
- **并行**：同一挑战者的 6 票（精品档 10 票）以 4 路并发执行。擂台赛的顺序语义不变，仍要求换位后结论一致才计票。

### 5. 多稿并行起稿（`chapter.ts`、`article.ts`）

候选稿本来就是互相独立的新请求，现在番茄以 3 路、头条以全部稿数并发。每稿仍按 `draft-N` 落盘；恢复时已完成的稿件不会重新调用模型；任何一稿失败时整单可恢复，与原来一致。粗算黄金章起稿耗时降到约 1/3，未实测。

### 6. 阶段输出容错（`workflow/schema.ts`）

- `jsonOutput`：先严格解析；失败后取第一个完整的 `{…}`（跳过字符串里的括号），把字符串里的裸换行、回车、制表符转义后再解析。长篇正文放进 JSON 时最常见的失败就是裸换行。
- 新增 `locate(body, quote)`：忽略空白和中英文引号样式的差异，在原文里定位引文，并返回**原文中的真实子串**，后续的修订范围检查继续按原文工作。
- 审读：不再要求模型回显 `bodyHash`，由代码绑定正文。让模型复制 64 位十六进制串只会增加失败机会，对正确性没有帮助。
- 阶段卡（`methods.ts`）：不再要求回显 `sourceHash`，规则编号一一对应的校验保留；生成阶段卡重试 2 次，并且不带作品材料（阶段卡是按方法全局缓存的）。
- 硬伤定位、事实链的正文与来源、记账证据都改用 `locate`。

### 7. 作者是最终裁判：有问题的稿件照样交付并标注（`editor.ts`、`chapter.ts`、`article.ts`、`WorkflowPanel.tsx`）

**问题**：两轮定向修订后仍有硬伤，或头条终审有硬伤，原来直接抛错，候选稿不交付。

**改动**：
- `editDraft` 返回 `unresolved: true` 和最后一次审读报告。
- 番茄：推荐稿标为“推荐稿（仍有待作者判断的硬伤）”，交付回执带 `unresolved` 和说明。
- 头条：终审硬伤、未解决的修订、删改后仍无来源的事实，都写入交付报告（`finalReview`、`unverified`、`unresolved`），作为工作稿保存，不会替作者交稿。
- 面板：交付带问题时显示一行醒目提示：“交付稿仍有未解决的硬伤或无来源事实……请判断后再采纳”。
- 头条质检硬闸（Python QA）两轮不过仍然失败，这是业务门槛，没有放宽。

### 8. 头条流程（`article.ts`、新增 `article-facts.ts`）

- **标题去重前移**：取最近 30 篇文章的标题，作为 `avoid` 传给标题矩阵阶段，解析时过滤；起稿的主标题撞车会触发重试。原来要等到全部写完、质检做完，最后一步才报“标题重复”。
- **事实链前移并可修复**：事实链移到质检之前。允许标 `unsupported`，有无来源事实时，写手做一轮“删改无来源事实”，再核一遍（`facts-1`），之后才进质检硬闸，所以事实修复本身也受质检检查。资讯稿禁止标 `fiction`，这条不变。
- `factChain` 拆到 `article-facts.ts`，`article.ts` 回到 400 行以内，架构守卫的提示清零。

### 9. 系统代理不劫持本地模型（`session/pi-adapter.ts`）

**问题**：设置了 `HTTP(S)_PROXY` 但 `NO_PROXY` 没写 localhost 时，本地的 Ollama、LM Studio 或中继请求也会被送进代理，结果失败。测试套件本身就暴露了这个问题：沙箱有系统代理时，桌面测试 64 项挂 36 项。

**改动**：`EnvHttpProxyAgent` 的 `noProxy` 始终追加 `localhost,127.0.0.1,::1`，作者原有的 `NO_PROXY` 保留。回归测试新增一种情况：清空 `NO_PROXY` 时访问回环地址，代理隧道数仍为 0。

### 10. 本地原典库（`packages/toutiao/src/classics.ts`）

从 3 篇扩到 9 篇，新增塞翁失马（淮南子·人间训）、守株待兔（韩非子·五蠹）、刻舟求剑（吕氏春秋·察今）、揠苗助长（孟子·公孙丑上）、夸父逐日（山海经·海外北经）、画蛇添足（战国策·齐策二），都是公版原文并附出处。故事线不用联网也有更多题材可写。**建议作者对照权威版本再核一遍字句**：事实链会用这些原文核对引文，原文有错字会一路传下去。

### 11. 服务商故障退避与余额不足暂停（`workflow/stage-model.ts`、`packages/core/src/workflow.ts`）

模型返回限流（429）、过载、5xx 网关错误或网络中断时，同一阶段内按 2 秒、6 秒、15 秒退避重试三次，取消会立刻中断等待；内容类错误（格式、字数）仍交给阶段自己的一次重试，不加次数。返回 402、Insufficient Balance、余额不足等时，抛出预算类错误，任务进入“已暂停”并保存进度，提示充值或换连接后恢复，日志不再为它多跑一次。新增 6 项测试（错误分类、退避成功、退避用尽、内容错误不重试、余额暂停、取消中断、日志不重试余额错误）。

### 12. 内核调用层（审查跟进）

依据内核审查第三节 A–H。不改业务规则和质检阈值，“作者是最终裁判”的交付语义不变，step id 全部不变，旧 journal 可照常恢复。下面的收益都是**估算，没有实测**。

- **A. 缓存前缀拆成 systemPrompt，并传 sessionId**（`workflow-config.ts`、`run.ts`、`stage-model.ts`）：`contextPacket` 改为返回 `prefix`（职责、本书设定、材料）和 `suffix`（方法、输入、作者要求、返回格式），两段拼起来与原包逐字相同。材料从后段移到前段。`completeSimple` 以 `systemPrompt` 发前缀，以 user 消息发后段，同时传 `sessionId=runId`、`maxRetries:0`、`timeoutMs` 6 分钟（这四项已在 pi-ai 1.4.0 类型里确认）。效果：Claude 系接口从每个任务的第 2 个阶段起，可以在前缀末尾命中缓存；DeepSeek 一类按前缀自动缓存的服务，行为不变。
- **#2 前缀稳定**（`contextPacket`）：可选材料采用 (b) 方案：遇到第一个放不下的可选块就停，之后的可选块全部让位，不再“跳过大块、收下后面的小块”。代价是预算紧时可能少带一两块靠后的小材料（这些块本来就按重要性排在后面）。必带块不受影响。
- **B. 读者投票**（`editor.ts`）：输入改为 `{A, B, persona}`；编辑方法卡换成固定的几行读者卡（`selectDraft` 去掉 card 参数）；先跑同一画像的两个位置各一票，预热两个前缀，其余票再按 4 路并发。种子票失败就整单失败，不再发后面的票。估算每票少带 1.5–2.5k 字方法卡；在按前缀自动缓存的服务上，同一位置的各票共享两篇正文的前缀。代价是选稿多一个往返的时延。
- **C. 头条来源进前缀，终稿未变不再重审**（`article.ts`、`article-facts.ts`）：来源原文作为必带材料“来源原文”放进前缀，立项卡、标题、结构、起稿、事实链、删改、精修各阶段的输入里只留 `{attribution, text:"见材料「来源原文」"}`。出处链接检查和事实链引文定位仍用真实原文。删改事实和质检精修都没有改动正文时（以 `editDraft` 末轮审读报告里的 `bodyHash` 判断），直接复用那份审读，不再调用 `final-review`。估算来源 1 万字时，约 9 万 token 改按缓存价计；常见路径每篇少 1 次 editor 调用。
- **D. 重试收敛**（`stage-model.ts`、`packages/core/src/workflow.ts`）：
  - 新增 `StageError{kind: balance|transient|truncated|provider, usage, retryable}`。
  - `stopReason==="error"` 时，先用 pi-ai 的 `isRetryableAssistantError`（已确认导出，签名为 `(AssistantMessage) => boolean`），再用原正则兜底，判断是否 transient。余额正则补上 `quota exceeded`、`out of budget`、`billing`。
  - 退避只剩 `withProviderRetry` 一层，并加 ±20% 抖动。退避用尽后的 transient、provider 拒绝和截断，journal 都不再整轮重来，只有内容校验失败才重试。一次阶段尝试最多发 4 次 HTTP（原来最坏约 24 次）。
  - 截断直接失败，用量照样记进 journal 和预算。
  - 内容重试时，在包尾追加“## 上次返回未通过校验”和失败原因（截到 600 字）。追加在包尾，不影响前缀。
  - 与审查稿示例的一处差异：示例里 provider 类错误仍可在 journal 重试，这里按审查正文“journal 层不再重试 transient 和 provider 类错误”处理。
- **E. journal 写入与并发预算**：`save()` 改为串行加合并。写盘时才序列化最新状态，旧快照不会再覆盖新快照；写失败时由下一次 save 重试。缩进保留，publish 仍在写盘后，未做节流。`WorkflowRun` 增加 in-flight 预留，并发阶段做预算预检时，会把彼此已预留的输入一起算进去。这只会更严，不放宽预算。
- **F. 自动记账让位暂停任务**（`session/manager.ts`）：定稿时，如果当前任务是暂停中的写作任务，就不启动记账，并提示“自动记账暂缓”。这样不会抢走恢复入口，也不会改动它依据里的连续性账本。补记排队（`pending-ledger.json`）留到下一轮。
- **G. 热路径缓存**：
  - 阶段请求按 `sha256(authPath, role, 连接设置)` 复用 ModelRuntime（`pi-adapter.ts` 新增 `stageRuntimeModel`，最多缓存 8 份，失败即删）。设置一改就换新键，所以没有接 reconfigure 清空钩子（那在 `main/` 里，不在本轮范围）。对话会话、测连接、模型目录仍然每次新建。
  - `host.key()` 按目标记住结果；目录还不存在时不缓存，避免记下未 realpath 的值。
  - 同一批并发阶段在 2 秒内共享一次新鲜度检查；交付前仍然每次严格检查。
  - `context.ts` 的番茄依据抽成 `fanqieDocument()`，构建和校验共用一份，去掉 `JSON.parse(snapshot())` 往返。basis 字符串与原来逐字相同。比较仍用字符串直比，不改成 sha256：两者等价，直比更省。
- **H. 日志**：`workflow_stage` 增加 cacheRead、cacheWrite、cost、packetTokens、prefixTokens、omitted、attempt、ms。以后用经济档实测时，可以直接算出命中率和让位情况。

测试：新增 5 项（带类型的 transient 退避用尽即终止、额度错误转暂停；截断不重试且用量记账并落盘；内容重试拿到上次失败原因；20 路并发 save 后磁盘为最新；真实请求路径下前缀进入系统消息、只发 1 次、截断保留用量）。两条完整流水线增加断言：重试包含“上次返回未通过校验”；前缀作为系统消息发送、不重复进 user；定稿不抢暂停任务的指针并给出提示；头条来源只在前缀里、阶段输入只留引用；终稿未变时不跑 final-review；读者投票先跑两个位置。假模型只加了一个可选的 `finish` 字段，用来模拟截断。

### 13. 前端交互（审查跟进）

依据前端审查第三节 QW1–QW8，另做 P19 与 P24 中三个小项。不改业务规则，不新增依赖。

- **流式增量瘦身**（`session/task-tracker.ts`）：`message_update` 只给主会话的 `text_delta` 发 `{type, delta}`，不再随每个 token 克隆 `message` 与 `partial` 两份累积全文，也不带 `task`/`focus`/`phase`；思考、工具参数增量和子会话增量不再推送（渲染层本来不用）。首字计时在转发前完成，不受影响。渲染层因此不再逐 token 写入新的 `task`，任务卡等不再逐 token 重渲染。
- **单一 IPC 订阅**（`renderer/state/desktop.ts`）：新增 `onDesktopEvent`，渲染层只挂一条 `writerDesktop.subscribe` 再扇出；主事件、上下文面板、工作流面板三处改用它，每条事件只跨 contextBridge 复制一次。
- **命令面板**（`CommandPalette.tsx`、`commands.ts`、`state/store.ts`）：查询词改为面板内状态，删掉全局 `query`；支持 ↑/↓、Home/End、Enter（中文输入法选词时不误触），列表为 `listbox`/`option` 并高亮当前项；按当前作品模式过滤命令（头条作品不再列出“新书”，未打开作品时全部列出）。
- **流式 Markdown 分段**（`AgentMessages.tsx`）：按空行切段（代码围栏内不切），已闭合段落由 memo 跳过重解析，只有尾段逐帧解析。

### 14. 前端深度优化

依据前端审查 P1–P24，分外壳、工作流面板、对话面板、编辑器四块改，再统一收口。不改业务规则、质检阈值与交付语义，不新增依赖。

**外壳与状态**

- 状态改为按字段订阅（`useDesktopSelector`），控制器只建一次、方法引用不变；顶栏、对话面板、写作区各取所需，面板数据变化不再整页重渲染。删掉 `AgentSlot` 与旧的 `DesktopController` 兼容类型。
- 提示统一进 `packages/ui/src/notify` 一个队列：成功/信息自动收起（悬停暂停），警告/错误留到作者关；写作台的提示也改走这里，删除 `use-notices.js` 与工作台自己的 `Notices`/`Toast`。
- 确认统一走应用内确认框（`setConfirm` 由外壳安装），离开判定 `canLeave` 一律异步；同一作品内的跳转（结果卡“查看”、对照采纳）就地切换，不重挂载写作区。
- 顶栏菜单、命令面板补全键盘与读屏语义（`menu`/`menuitem`、`listbox`/`option`）；快捷键按平台显示（macOS 显示 ⌘）；层级统一用 `--ui-z-*` 令牌。

**工作流面板**

**对话面板**

- 上下文面板只留占用、本任务与会话用量、手动压缩与详情；自动压缩开关、阈值与预算移到“设置 › 写作引擎”。

**编辑器**

## 四、未做与风险

1. **没有真实模型验收**。以上节省和提速都是按结构估算，不是实测。建议余额允许时，用经济档写 1 章、写 1 篇头条，对比阶段用量和耗时。
2. **并发与限流**：起稿 3 路、投票 4 路。如果服务商限流很严，可以把 `DRAFT_CONCURRENCY` / `VOTE_CONCURRENCY` 调成 1。多路并行时预算检查原本是近似的，可能略超一个阶段；第 12 节已加并发预留，这一点已消除。
3. **容错解析**只修复 JSON 层面的问题，内容校验（字数、占位符、编号覆盖、篇幅变化 30%）一项都没放松。
4. **旧默认预算自动升级**：作者如果是有意设成 200000，会被改成新默认值。这是有意的取舍，已写进 CHANGELOG。
5. 已推送分支 `opt/workflow-hardening`，GitHub CI（含 Windows 桌面测试、构建与 GUI 旅程）在第一轮提交上全部通过；Windows 安装与升级手工清单仍未做。
