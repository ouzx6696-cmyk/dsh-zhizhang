# 0.4.0 交付说明

本次按用户最新明确要求，将织章源码迁入主仓库并允许修改；这覆盖此前“不修改 vendor/zhizhang”与“两套 linter 并存”的约束。本次不修改原 Skill 的判分规则、头条固定末句与业务状态契约。

## 改动文件

完整逐文件列表见 `0.4.0-changes.txt`。主要改动：

- 新增 packages/zhizhang 完整源码、原测试、客户端和维护文档；内部模块 private，版本跟随主包。
- packages/app/src/index.ts：统一配置/挂载、合并 linter 回调、项目主会话目标与按钮投递。
- packages/dsh-adapter/src/index.ts：原生工具注册、可选 Schema、scoped 执行与 sessionController.prompt。
- packages/fanqie/src/zhizhang.ts：改用内部作品选择及章纲/正文读取，删除磁盘格式解析。
- packages/fanqie/src/env.ts、tools.ts、gates.ts：作品级回报、working_dir、移除独立 linter。
- packages/zhizhang/src/lib/writer-hooks.ts、storage/chapters.ts：共享定稿门禁与回报读取。
- packages/zhizhang/src/lib/http-api.ts、client/components/Inspector.jsx：原接口增量扩展、右栏摘要与操作按钮。
- 构建、pnpm lock、CI、迁移文档、新整合测试和原测试哈希清单。

## 接口变化

- 安装包只有 dsh-writer@0.4.0，初始工具 toutiao_enable / fanqie_enable / zhizhang_enable。
- 织章参数只配置在顶层 zhizhang；原 fanqie.zhizhang 重复配置会报明确迁移提示。原目录、数据格式及面板 URL 不变。
- 删除 fanqie_manuscript_lint，改用 zhizhang_style_lint 的织章雷达 + forge 体检结果。
- 编辑回报写入作品 writer-reviews/<章id>。不改原 meta、章节和候选格式。
- 原章读取接口新增 meta.writerReview；新增 POST /api/dsh-zhizhang/writer/action，body 为 {base?,work,chapter,action:continue|review|revise,confirm:true}。
- 正常 author 确认、版本检查及原 gate 继续生效。NO_AGENT 这一旧 writer 扩展错误码已收回到契约 INVALID_ARGS，恢复规定的七种业务错误码；织章原错误格式保持兼容。

## 已知限制

- 本次有真实 headless、HTTP、源码客户端构建验证，没有 Windows/macOS 桌面实点和真实模型试写；不宣称这些人工验收已经通过。
- 主会话投递目标保存在宿主进程内，重启后需先在对应主会话使用织章，避免猜目标或误投其他项目。
- 0.3.0 外置历史审读回报不自动移动；原稿件无需迁移，旧回报可在备份后复制对应章目录，或重新派编辑审读。
- 源码包不含 node_modules/build/dist；安装包包含运行所需编译产物、Skill 和原始方法/规则资源。未引入新的第三方业务运行时依赖。

## 上游建议

织章已归入本仓库维护，本次没有待外部织章上游实现的阻塞。DSH 后续若提供可持久查询的项目主会话选择接口，可替换当前进程内记录；本版坚持使用已核实的 rc.4 prompt 接口。没有向外发送消息、开 PR 或发布到 npm。
