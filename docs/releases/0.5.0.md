# 0.5.0 — 写作任务与工作台

0.5.0 以 `dsh-writer 0.4.0` 为基础，将头条、番茄与小说工作台组织为可恢复的写作任务。插件沿用 DSH 的模型、会话和工具执行能力，原文章和小说目录保持可读。

## 主要变化

- 默认提供头条与番茄两个入口；旧 `zhizhang_enable` 可通过兼容配置启用。番茄工作台通过 DSH 的作用域工具执行管线加载。
- `writer_run`、`writer_status`、`writer_resume`、`writer_checkpoint`、`writer_review`、`writer_export` 管理任务、审读与导出。任务记录与稿件分别保存，以实际版本和产物恢复。
- 一项任务绑定文章或作品、章节、存储根与会话。多会话时明确选择目标；接管任务后，旧会话不能继续写入。小说右栏续章从当前选中章向后定位。
- 新文章和新作品预留标识；任务创建新书使用 `strict_key=true`，已有或不完整目录不会变成第二本书。候选损坏或登记章节文件缺失时明确报错。
- 新一次审读不会直接沿用旧结果；严格模式要求独立编辑对当前正文完整回读、零硬伤并通过。新旧回报按实际记录时间读取，旧版本回报继续可用。
- 写作包按当前章节筛选相邻正文、规划与连续性。工作台提供模式切换、任务查看、版本对照和导出；页面切换时保留已打开的小说工作台状态。
- 任务页和头条页统一检查本机地址、Host 与 Origin；小说 API 继续使用原有访问策略。发行包只包含运行所需文件，排除测试夹具。

## 执行与恢复

DSH Agent 负责推理和调用业务工具；任务层不另起模型循环。任务记录保存于项目 `.writer/tasks/`，导出位于 `.writer/exports/`。中断后在原项目主会话启用模式并恢复任务；模型请求或会话投递结果不明时，不自动假定请求没有执行。

取消任务会阻止后续任务写入，已保存稿件保留；它不会声称已取消宿主发出的模型请求。连续性变化作为待确认摘要，正式设定仍由原作品工具维护。异常退出留下写锁时，先确认没有其他写入进程，再核对锁和任务记录。

## 检查结果

在 Linux、Node 24.19.0、TypeScript 5.8.3、Python 3.11.17 和 DSH `dsh-v0.2.1-rc.4` 下：

- `pnpm check`：项目与真实 DSH 组件 41 项、小说引擎 47 项全部通过；长篇 Python 桥 10 项通过。默认检查只编译一次。
- 真实 DSH headless 宿主中，头条与番茄两种模式均完成模拟模型的写手 / 编辑工具流程；检查了任务绑定、版本回报和作者确认边界。
- 实际本机 HTTP 检查了全部工作台路由的注册，以及代表性的读写、方法、来源和访问控制。Chromium 检查了模式表单、文章创建以及切换页面时保留工作台状态。
- 头条规则库的 205 项历史检查本轮单独运行通过；它保留为规则变更时的可选 `pnpm test:rules`，不重复纳入默认检查。

headless 验收使用模拟模型，浏览器检查使用本机宿主模拟。真实模型试写、目标 DSH 桌面实点和 Windows/macOS 真机验收尚未完成。
