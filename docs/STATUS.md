# 开发状态

当前源码版本 **0.20.0，未发布**。公开安装版本仍为 0.19.0；源码提交与发行包发布分别管理。

## 当前流程

作者通过工具或面板读取作品依据，生成候选，经明确采纳成为现行稿，再按实际授权审读、定稿。改稿保留历史并核对关联依据。表达诊断提供本地规则及重复统计，作者按段修改后保存为候选，沿用同一采纳与恢复流程。

写作台只读取作品摘要和按需正文；全书概况另读参考库与灵感库。查询不增加授权，缓存不作为写入完整性凭证。网络结果不确定时核对同一请求，文件写入中断由已有恢复协议处理。

## 性能与结构

- 章节摘要共用投影，批量读取并限制并发；每批只检查一次恢复状态。摘要缓存按约 8 MiB 总占用限制，去掉 400 章的重复条目上限，避免长篇轮询反复淘汰和重读。
- 扫描保留有序的前 120 条，超出显示范围只计数，不反复构造并排序结果；文本掩码使用字符串片段。
- 撤销与重做按字符串占用控制历史，输入时不再序列化整份历史。
- 客户端只登记当前 DSH 的三个席位，资源随 fiber 释放；宿主控件在加载时选择，渲染错误由页面边界报告。
- 移除重复兜底、旧设置席位、无用测试出口与 bun-types；历史设计、阶段记录和开发检查脚本留在仓库，不进入安装包；安装包保留离线备份工具。

同一 Linux / Node 24 环境，五次测量中位数；快照样本为 160 章、60 个候选，编辑样本为 80 次修改一个 4 万字段落。时间为本地样本，不是目标桌面的性能承诺。

| 操作 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 36 万字节密集命中扫描 | 322.35 ms | 38.21 ms |
| 34.56 万字节重复叙述扫描 | 80.00 ms | 12.15 ms |
| 长段落连续编辑与撤销 | 391.41 ms | 0.99 ms |
| 写作台快照 | 229.07 ms | 42.19 ms |

另外单次对照 600 章缓存：两边冷读均为 600 次；热刷新正文读取从 600 次降到 0 次，耗时 506.76 → 41.70 ms。两边使用相同章节文件；这是缓存行为核对，未作为常驻计时断言。

## 校验

测试围绕规则、工具入口、HTTP 和文件恢复四种职责组织。合并重复状态与客户端装载检查，完整创作主线保留一条，版本与依赖检查直接设置必要前提。真实中断、并发、坏文件和原稿保留检查继续运行。

Node 22.23.4、24.19.0 各通过 **47 项检查**，104 个 TypeScript 模块无运行时依赖环。另以 60 组混合文本核对优化前后的诊断结果，输出一致。真实 React 18 与 Chromium 核对了 work → all → work 范围切换、扫描、编辑、撤销重做、提交后丢失响应的同请求重试、迟到响应隔离与四种宽度，未出现页面脚本错误。使用插件内控件，未启动实际 DSH。检查数量不是质量目标。具体入口见 [测试说明](TEST.md)。
