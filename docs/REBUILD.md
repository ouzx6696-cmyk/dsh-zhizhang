# 织章重构契约（实施中）

本文件约束本轮实现。目标是参考书的证据能迁移进本书规划和正文，作者能了解并控制实际发生的变化。现有作品与库资产继续可读；本文件中的目标不等于均已实现。

## 当前进度与交接

本轮工作处于阶段性重构，尚未完成全部目标。以下状态用于继续实施时定位，不代表已经上线或发布。

### 已完成的阶段性工作

- 存储：拆分作品元数据、章节和底层文件操作，保留原有入口；保护损坏数据，避免并发创建同名作品时复用既有目录，并减少单进程内更新互相覆盖。
- 拆书证据：区分阅读计划、实际交付和事实；阅读程度由使用者如实声明，旧记录不推断已读。新 v2 卡保留引用章节的声明与书源校验信息，书源变化时要求重核。
- 规划与续写：支持不使用卡片直接规划及作者明确选择的节奏；全书、卷与幕规划作为独立候选，经显式应用后进入对应章简报及面板。章简报保留长前章开头和实际结尾，标明截断或缺失；状态更新尽量保留作者手写内容。
- 中断恢复：正文候选暂存、扫描和采纳、直接保存章节、简报和兑付留痕、技法卡采纳、书源导入、删卡、拆书计划及分析更新和灵感应用各有恢复记录、冲突检查及工具入口；相关面板能提示异常，避免把不可读数据显示为空。新扫描凭据绑定正文，旧凭据需重新扫描。
- 库初始化：避免首次并发创建索引时读取半成品；发现已有资产但缺少索引时不自动创建空索引。拆书计划的正文、可读视图、进度元数据和全量确认凭据一起恢复。
- 跨进程写入：拆书分析工具、灵感会话和候选及既有作品、库写入接入相应资源锁。新增离线备份脚本，要求指定来源及新目标，并校验文件内容。

### 部分完成与尚未完成

- 全书、卷和幕规划已可暂存、显式应用并进入章简报；历史通过已采纳候选保留并可查看；完整可视化编辑仍未实现。现有已发生状态的自动摘要只是有限的辅助，不是完整的故事记忆或连续性系统。
- 阅读程度是申报信息，不能证明 Agent 实际读过或理解原文；旧卡不会自动补造证据。并非所有派生数据和多文件操作都有恢复记录；旧版本没有记录的中断须人工核对。
- 拆书库的书源导入、卡暂存、采纳、删除、索引校准和卡采纳恢复，以及作品的根基、章节、候选、审校和相关留痕写入，已使用各自的跨进程写锁；主要拆书分析工具及灵感会话和候选也已接入；直接调用底层写文件接口、外部编辑等路径仍未被统一协调。断电持久性、Windows 文件系统和真实 DSH 宿主尚未验证；面板提供提示，恢复操作目前通过工具完成。
- 离线备份支持复制、完整性校验和识别符号链接，但不自动恢复或迁移；旧资产异常、跨平台文件元数据和批量迁移仍需单独处理。测试统一由 `npm run check` 执行，覆盖主线、数据恢复、并发及面板安全。

### 已验证的范围

当前 Linux 环境下 `npm run check` 通过构建、静态护栏及 29 项测试；此前还用临时探针验证了部分中断恢复、冲突及并发场景。临时探针在 `/tmp`，不是仓库内长期测试；这些结果不能替代真实 DSH 宿主、Windows 或断电场景验证。云环境安装配置此前已保存为待审核草稿，尚未发布。

### 恢复后的顺序

1. 先读本文件并检查工作区，保留当前全部改动；按需要恢复依赖并确认构建，重新核对尚未提交和未跟踪的源码、文档及 `dist` 文件，避免遗漏。
2. 核对跨资源写入、底层直写和锁的归属及顺序；不能仅凭超时清锁，并验证相关文件系统行为。
3. 按数据风险扩展其他多文件操作的可恢复性，并完善备份、迁移和异常资产的处理；保护恢复期间的作者修改。
4. 继续完善全书到章节的规划交接、小说状态和作者界面，使拆书证据、规划、写作和作者决策形成可控闭环。
5. 测试已精简为四个文件，由 `npm run check` 统一校验；条件具备时在真实 DSH 宿主及目标平台验收。

当前所有工作尚未提交；新增源码、本文档及部分构建产物仍为未跟踪文件。后续整理提交时须同时检查已跟踪改动和未跟踪文件，不应只依赖 `git diff`。后续按上面的顺序继续实施。

## 业务对象与交接

- 参考书：原文和章节索引。代码测绘、发给 Agent 的原文、已提交事实、深度判断分别表述；发出文本不证明已经阅读或理解。
- 事实：引用可核对的记录；解释和可迁移方法保留来源、阅读范围、适用条件与失败边界。既有 v1/v2 卡继续可读，不凭旧字段推断深读。
- 创作规划：作品根基与纲是可修改的工作成果。mind 主要供规划，craft 供场面与正文；无卡可直接规划，不能虚构来源。
- 章节：正文、纲与候选分开；brief 使用可确认的前章内容，缺失与截断必须明示；已采纳不等于定稿。
- 小说状态：已发生、计划、线索、人物/读者知识分别表达。自动提议须能追溯且不得覆盖作者手写事实；修订旧章后不把旧记录冒充新事实。
- 决策：暂存、扫描、采纳、应用、定稿各有独立结果。面板与工具共用业务入口，回执只声称已完成的事。

## 数据与兼容

- 现有 Markdown、JSON、JSONL、卡和索引为用户资产；不可因解析或权限失败当空文件覆盖。不存在与损坏分别处理。
- 新元数据以可选字段或新文件引入；旧资产按已知事实读取，缺失证据显示未知，不推断已读或已审。
- 任何批量迁移须先设计可恢复步骤并保留原件；本轮不自动改写既有资产。
- 进程内锁不构成跨进程保护；拆书库和作品已接入的写入路径各自共享跨进程写锁，拆书分析工具和灵感会话已接入各自资源锁；底层直写、外部编辑及跨资源操作仍需单独核对。

## 候选采纳恢复（已实现，范围有限）

- 正文、作品摘要与小说状态、候选标记、审校留痕在写入前保存同一份采纳意图；每个文件保存原始字节的前后校验，候选正文另作只读校验。恢复记录包含候选正文，仅在作品目录中保存，创建时请求仅所有者读写。
- 被中断时正常读写会提示待恢复。用 `zhizhang_status(work=作品, recovery=inspect)` 查看文件状态；确认无冲突后使用 `recovery=resume`。恢复按原内容完成写入，不重新执行 append，也不覆盖其他章节或作者手写状态。
- 恢复前及写入过程中发现文件变化时停止，保留恢复记录并要求人工核对。原进程在其他 PID 中仍存活、主机不同或无法确认时，不自动恢复；不能只凭超时清锁。
- 这是正文候选采纳的恢复；直接保存章节、书源导入和灵感应用各使用独立恢复记录。参与作品写锁的进程会串行写入；不参与锁的外部程序或手动修改仍不受保护，操作系统或电源故障的持久性也没有被保证。
- 恢复记录损坏或冲突时不可自行删除；应保留现有文件和记录，先备份并人工核对。旧版本已经部分写入但没有恢复记录的操作也需要人工核对。
- 作品写锁位于作品目录的 `.zhizhang-write-lock`，正常退出后移除。异常退出遗留锁时，先确认所有相关写入进程停止并核对锁记录，处理遗留锁后再检查或恢复采纳；不会仅凭超时自动清锁。
- 新扫描凭据绑定被扫描的正文。旧候选缺少正文校验的凭据时必须重新运行 style_lint；候选内容保留不变。


## 技法卡采纳恢复（已实现，范围有限）

- 显式采纳前，在拆书库写入记录，包含卡文件、索引和候选状态的原始字节前后校验。v2 模块额外核对书源及书源元数据；记录含卡片和索引内容，创建时请求仅所有者读写。
- 采纳中断时用 `zhizhang_library_list(recovery=inspect)` 检查；无冲突且同一进程的原操作已结束或原进程已停止时用 `recovery=resume` 完成原操作。恢复不会创建第二张卡；文件、候选或书源有变化时停止，不覆盖作者修改。
- 面板拆书库区域显示不可读和恢复指引，不把待恢复库当成空库。缺失索引但仍有原文、卡或候选时不会自动创建空索引。
- 卡采纳、书源导入和删卡各使用独立恢复记录，均由 `zhizhang_library_list(recovery=inspect|resume)` 检查或恢复。旧版本没有恢复记录的中断需保留文件并人工核对。
- 初始化索引用完整临时文件及不覆盖链接，避免并发首次创建时读取半成品；书源导入、卡暂存、采纳、删除、索引校准和卡采纳恢复使用跨进程写锁。主要拆书分析工具也使用库锁；底层直接写文件和外部程序不在此锁保护范围。尚未验证断电持久性或真实 DSH 宿主、Windows 文件系统行为。
- 写锁位于库目录的 `.zhizhang-write-lock`，正常退出时移除；等待超时不自动清锁。若进程中断留下锁，先确认所有相关写入进程已停止，并备份、核对锁记录及待恢复操作，再人工处理；不能只凭时间或 PID 作判断。

## 本轮新增的恢复与规划

- 直接保存章节或章纲、暂存和扫描候选、更新简报或兑付留痕时，使用作品目录中的 `.zhizhang-chapter-pending.json`；用 `zhizhang_status(work=…, recovery=inspect|resume)` 检查或恢复。
- 灵感应用的恢复记录位于灵感目录，作品目录有待恢复标记；用 `zhizhang_inspire_status(recovery=inspect|resume)` 检查或恢复。文件变化时停止，不覆盖作者修改。作品新建本身发生在恢复记录之前：如果新建后尚未开始应用就中断，可能保留空作品，需人工核对。
- 书源导入使用临时源文件与恢复记录，不把整本原文写进 JSON 恢复记录；删卡有独立恢复记录。中断时用 `zhizhang_library_list(recovery=inspect|resume)`。在恢复记录建立前中断可能留下无索引的临时文件，不能当作已导入，应保留并核对。
- `inspire_stage` 支持 `book_plan`（`content`）、`volume_plan`（`id`、`title`、`content`、可选 `chapters`）及 `act_plan`（可另填 `volumeId`），显式 apply 后写入作品可选 `planning` 字段。章简报仅注入关联本章的卷和幕；`zhizhang_inspire_status(work=…)` 可查看完整规划，`history=true` 可列出已应用的候选，`candidate=…` 查看原候选；恢复旧方案须重新暂存并显式采纳。面板显示摘要。来源记录作者目标和选择过的卡，不推断实际阅读或具体影响。
- 离线备份：停止所有相关写入进程后，用 `node scripts/backup.mjs --source <目录> [--source <目录> ...] --output <新的备份目录>`；用 `node scripts/backup.mjs --verify <备份目录>` 核对。不会覆盖已有目录；备份期间变化会留下未完成标记。符号链接只保存链接，不包含目标；脚本不保证跨平台文件权限、时间戳或断电持久性，不自动恢复。
