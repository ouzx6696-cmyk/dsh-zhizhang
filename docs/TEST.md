# 测试与校验

在源码仓库使用 Node ≥22：

```bash
npm run check  # 静态护栏、依赖方向、构建和全部测试
npm test       # 构建并运行测试
```

日常使用 `npm run check` 即可。测试直接运行构建后的发行代码，包含一条精简的拆书到续写流程，以及针对高风险边界的检查；没有另外维护长篇端到端剧本或独立烟测。

| 文件 | 关注点 |
| --- | --- |
| `test/workflow.test.mjs` | 主线、条件接续、审读/定稿、参考迁移、配置隔离及按需挂载 |
| `test/domain.test.mjs` | 末拍、章节和旧卡兼容、软检测及编辑确认 |
| `test/storage.test.mjs` | 资产损坏保护、恢复冲突、真实写入失败、多进程和备份 |
| `test/panel.test.mjs` | 面板读写、生命周期操作、版本冲突、访问控制、限流及客户端加载/安全渲染 |

测试用临时目录，并在测试进程中隔离 `DSH_HOME`、作品和拆书库等环境变量，避免修改真实资产。存储测试包含独立进程及模拟写入失败；备份测试只使用临时文件。

新增或修改测试时，优先覆盖用户可观察的行为和资产安全，不固定工具总数或长段提示文案；避免为同一条流程再增加多个脚本。跨平台文件系统、断电和真实 DSH 宿主仍需在相应环境中另行验收。

TypeScript 原生检查类型导入和未使用的声明/参数；现有架构脚本检查依赖方向、循环及禁止关闭类型检查，无需迁移基线或同名类型的正则推断。

CI 使用 Node 22/24 运行相同命令。静态架构检查不替代行为验证；客户端模块装载与渲染检查不代表真实 DSH 桌面已验收。
