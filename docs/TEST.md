# 测试与校验

在 Node.js ≥22 的源码仓库中运行：

```bash
npm ci --ignore-scripts
npm run check
```

日常完整入口只有这一套。`check` 运行架构检查，再编译 TypeScript、构建客户端，最后执行四个测试文件。服务端与客户端行为检查加载发行代码，段落编辑状态单独检查纯函数。所有资产操作使用临时目录，并隔离 DSH home 与相关根环境变量。

## 四种职责

| 文件 | 唯一职责 |
| --- | --- |
| `domain.test.mjs` | 纯规则、源位置、编辑状态、配置与版本隔离；不搭建 HTTP 服务 |
| `workflow.test.mjs` | 一条参考到写作的完整主线，以及工具授权、来源与依赖契约 |
| `panel.test.mjs` | 实际 HTTP 路由、读取范围、缓存失效与访问限制；统一客户端模块边界 |
| `storage.test.mjs` | 原稿、历史、坏文件、真实写入失败、恢复冲突、进程并发与备份 |

同一规则只在所属层验证。状态函数直接导入，不为其重载整份客户端；测试使用同一套临时目录与隔离辅助。不另建烟测、端到端平台或独立测试 runner。

## 静态边界

TypeScript 启用 strict、类型导入、未使用声明与参数检查。架构脚本解析运行时依赖，拒绝循环、存储反向依赖及关闭类型检查，并限制文本解析与诊断领域代码引入服务端基础设施。客户端由实际 esbuild 构建验证。

这些检查不能证明任意动态导入、宿主行为或文学语义正确。

## 当前验证证据

实际检查数量、性能样本和待验收项统一记录在 [开发状态](STATUS.md)。Node 22/24 的 CI 使用同一完整入口；工作流配置不等于未提交代码已通过 GitHub CI。

浏览器使用真实 React 与实际本地 HTTP 接口进行必要交互核对，不把临时浏览器脚本发展成常驻长流程套件。真实 DSH 桌面、宿主控件和平台兼容仍需对应环境验收。

## 维护原则

改变资产写入或版本规则时，检查成功结果、拒绝条件及中断后的恢复；改变缓存时，将真实快照、正文接口与 reducer 组合验证。避免只给手写快照添加字段，或把提示文案和工具总数锁成脆弱断言。

文档修改检查链接、命令、参数和打包结果，不为可逆文案新增测试。开发与交付步骤见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
