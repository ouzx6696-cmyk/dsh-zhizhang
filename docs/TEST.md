# 测试与校验

在 Node.js ≥22 的源码仓库中运行：

```bash
npm ci
npm run check
```

日常完整入口只有这一套。`check` 先运行架构检查，再编译 TypeScript、验证并复制客户端，最后执行四个测试文件。测试加载发行代码，避免源码通过而 `dist/` 未同步。

## 四类验证

| 文件 | 关注行为 |
| --- | --- |
| `test/domain.test.mjs` | 确定性领域规则、末拍与证据、旧卡适配、机械诊断及编辑授权 |
| `test/workflow.test.mjs` | 精简主线、规划应用、条件接续、审读定稿、插入前章、参考迁移及多实例隔离 |
| `test/storage.test.mjs` | 原稿保留、损坏资产、真实写入失败、恢复冲突、多进程操作及离线备份 |
| `test/panel.test.mjs` | 面板读取/采纳/生命周期、版本冲突、访问规则、限流和客户端模块加载及安全渲染 |

测试使用临时目录，并隔离 DSH home 与相关根环境变量，不在真实作品上运行。故障、并发和备份测试保留必要独立进程，但没有另建烟测或长篇端到端脚本。

## 静态检查

TypeScript 原生检查 strict 类型、类型导入、未使用声明和参数。架构脚本识别源码运行时依赖、检测循环、限制存储反向依赖，并拒绝关闭类型检查。

这些检查可以发现特定结构问题，不能证明任意动态导入、外部宿主或文学语义正确。

## 已有证据与验证边界

0.19.0 在 Linux x86_64 / Node 22、24 上各通过 44 项测试，101 个 TypeScript 源模块未发现运行时依赖环。新增检查仍在 panel 文件内，覆盖旧项目响应隔离、正文失效/刷新、响应体超时、详情卡包身份和两种配置 schema。

本轮另以真实 React 和无头 Chromium、实际本地面板接口，完成 1440/1024/768/390 四种宽度下的布局、并排对照、采纳/审读/定稿、弹窗持续输入、手动重取正文及同名作品跨项目切换检查；使用插件内控件回退，未启动真实 DSH，也未加载宿主 ui-primitives。附件原有的 arm64、明暗主题报告不作为本轮复验结论。临时浏览器核对不增加常驻端到端脚本。

0.18.0 功能提交 `fa0818b` 曾在 Node 22.23.4、24.19.0 上各通过 39 项测试。以上均为特定版本的实测记录，后续结果以实际命令和 CI 为准，不把测试数量作为质量目标。

CI 在 Node 22/24 上运行同一 `npm run check`。已配置工作流不代表某次提交的云端执行已经通过；报告时区分本地结果与实际 CI 状态。

真实 DSH 桌面、Windows 文件系统、反向代理、任意外部竞态和断电持久性仍需相应环境验证。客户端模块协议检查不能替代桌面验收。

## 维护测试

针对本次实际改变的用户行为和资产风险选择验证。优先覆盖成功结果、明确拒绝及原数据保留，避免重复走同一主线，或把大段提示文案、工具总数锁成脆弱断言。

文档修改优先检查链接、命令、示例参数和打包结果，不为可逆文案新增测试。完整命令和交付步骤见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
