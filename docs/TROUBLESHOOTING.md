# 常见问题与排错

先确认插件是否加载、会话是否启用、项目目录是否一致，再处理具体错误。不要用重复保存、重新采纳或删除锁来代替定位问题。

## 找不到工具或面板

| 现象 | 先检查 |
| --- | --- |
| `zhizhang_enable` 也没有 | profile 是否已加入依赖并启用 bundle；修改后是否重启 |
| 只有 `zhizhang_enable` | 这是默认状态；让当前会话 Agent 调用它 |
| `no_agent_ctx` | 调用是否来自具备 Agent 作用域的 DSH 会话；独立 HTTP 调用不能代替会话启用 |
| 工具可用但面板不显示 | 插件客户端是否完整，侧栏席位是否加载；核对 `dist/client.js` 和宿主版本 |
| CLI 无法 dump desktop profile | 可能由 Electron 独占，改用 GUI 和启用回执核对 |

安装方式见 [DSH_INSTALL.md](DSH_INSTALL.md)。仓库自动检查通过不代表任意 DSH 版本都已实测。

## 工具写了，面板却找不到

核对工具回执中的实际作品根与面板所选项目。`working_dir` 本身就是数据根；独立 `worksRoot` 和 `libraryRoot` 可能在其他位置。先在目标会话调用 `project_list` 或 `project_open`，让面板发现项目，再选择对应作品。

如果使用相对路径，不同会话 cwd 或宿主 cwd 可能产生不同目录。固定根配置优先使用绝对路径。

## 候选不能采纳

| 错误或情况 | 含义与处理 |
| --- | --- |
| `brief_required` | 没有符合门禁的上下文记录；先获取本章简报。显式旁路不代表可以跳过真实版本冲突 |
| `lint_required` / `lint_token_mismatch` | 已有扫描凭据不再有效，或显式传错 token；对当前候选重新扫描 |
| `revision_conflict` | 目标正文、章纲或位置已变化；读取现行版本后重做候选，避免覆盖后来修改 |
| `context_changed` / `dependency_changed` | 必要根基、规划、前稿或章序变化；重核接续并重新准备 |
| `candidate_changed` | 候选在检查期间变化；重新读取和核对 |
| `legacy_baseline_required` | 旧候选无目标版本；明确传当前 `expected_revision` 或重新暂存 |
| `refuse_overwrite_final` | 正在修改定稿正文；只有实际授权修订时才传 `force=true` |
| `candidate_already_accepted` | 候选已经应用；先读现行章，不重复采纳 |

默认采纳内置扫描，不需要为了取得 token 例行先扫；但已有过期记录不会被静默忽略。开启 strict 策略后，命中可能按用户选择成为硬拒。

## 不能定稿

`review_required` 表示缺少当前正文版本通过的审读声明，或正文不满足定稿条件。先完整阅读正文及必要依据，记录当前 revision 的审读结论。

`dependency_not_final` 表示所依赖前章还未定稿；工作稿可以条件连写，但不能把未核前稿当作已定稿依据。审读结果为 `blocked` 时先解决问题，再声明实际通过的版本。

修改正文后不能把旧审读带到新正文。确认修订提示只清提示，也不能代替重新审读。

## 保存后报待恢复

`recovery_required` 可能表示部分目标已经写入，不是“什么都没发生”。先停止重复操作，用 [DATA.md](DATA.md#中断后先检查再恢复) 中对应的 inspect 入口查看实际文件与原意图。

确认原写入者停止且无冲突后，再考虑 resume。存在外部修改、跨主机进程或未知锁持有者时保留现场，备份后人工核对，不按锁时间自动删除。

## 面板 403、429 或正文截断

- **403**：检查访问来源、Host/Origin，以及配置令牌是否已在设置卡输入。本机也需要满足配置令牌；代理转发还需核对实际请求主机名。
- **429**：请求过于频繁，减少重复操作并稍后重试；不要同时反复点击采纳。
- **正文截断**：面板读取有大小上限，需通过工具补读，不能直接声明已完整审读。

## 参考和汇编结果与预期不同

引文未命中时检查原始字句、空格、标点与来源版本，不把转述强行标成引文。重复章号需明确位置，不能假设数字唯一。

汇编默认收录有正文的章节；`only_final=true` 兼容收录 `reviewed` 与 `final`，不会自动重新审读。被选章节坏损时终止并保留旧输出。没有正文时也不会生成空成稿冒充成功。

## 报告问题时提供什么

提供插件版本、Node/DSH 版本、操作和错误码、是否使用独立数据根，以及已去除正文隐私的最小复现。不要提交令牌、个人环境文件或完整作品目录；先保留原资产，再使用临时副本复现。
