# 0.9.2 审查修复记录

日期：2026-11-01（香港时间）。依据 [深度审查报告](0.9.2-REVIEW.md)，保留现有业务内核、DSH 与 Pi 宿主边界、方法资产和测试入口，统一修正对象、版本和状态在调用链中的传递。

| 审查项 | 修正结果 |
|---|---|
| R1 作者采用 | 页面捕获已加载文章及 rev／sha256，加载中或选中对象不一致时禁用；服务端在同一次串行更新中核对版本、验收和有效质检。旧页面不能采用后来生成的新稿。 |
| R2 验收统计 | 每套方案固定 18 个任务 ID，记录文章／版本与作品／章节；按实际产物核对类别、十章章纲、同书正文、独立编辑身份和当前指纹。缺项、重复和过期回报单列，分母保持 7 篇／10 章；评分也按任务 ID 对应。 |
| R3 发布引用 | 上传前解析轻量或附注标签的实际提交，与构建 SHA 比较；不一致即停止。缺少标签时仅创建指向该构建的标签，不强制移动旧标签。 |
| R4 候选定位 | 写手、编辑和整理候选通过现有执行上下文传递实际 ID、章节和作品；结果卡与阅读偏好保存该 ID，多份候选时仍打开指定稿。中文回执不作为结构化数据源。 |
| R5 发布正文 | 导出直接读取完整当前稿，不再复用有长度限制的页面预览；统一换行、去重标题、清理实际使用的配图标记，检查最终输出。 |
| R6 作品占用 | 显式重开同一作品也重新认领并刷新只读状态；认领和释放使用一致的规范路径，兼顾目录已删除时的进程清理。 |
| R7 方法草稿 | 方法面板报告未保存和保存中状态，作品／结果跳转复用现有离开检查；取消离开后保留草稿。自动建书跳转也经过同一检查。 |
| R8 配置恢复 | desktop、model、search、writer 配置共用对象读取入口，null／数组等错误形状走默认配置和提示。 |

联动复核还修正两处真实流程问题：新建方法方案的 `base=default/original` 不再被误认作作品目录；写入期间的正文读取失败，在下一次实际快照刷新时失效并重新读取，避免任务完成后仍停留在临时错误。不增加定时重试或新的恢复服务。

## 校验方式与结果

沿用既有入口，没有新增测试套件、烟测层或端到端矩阵。仅在相关场景补充版本冲突、双候选定位、方法草稿取消离开、配置对象和完整导出的断言。

- Python 规则：既有 205＋10 项通过。Node 业务检查的旧组件夹具已同步采用就绪状态；相关文件定点复核通过，完整检查由同一提交的 CI 执行。
- 桌面核心：原有 5 个场景通过，包含真实 Pi SDK 与本地假模型、跨进程占用及路径别名释放、配置恢复、超过预览上限的导出与 DOCX。
- 真实 DSH ToolRuntime：既有集成场景通过。DSH headless 与 Windows 复核继续由 CI 执行。
- 公共与桌面 TypeScript、生产构建通过；既有 3 个 Electron 场景覆盖新建书、布局与主题、候选选择、方法草稿离开检查、命令和新对话。
- 隔离统计反例：两套方案各 10 份当前编辑回报均可计入；各替换为 5 份过期回报和 5 份写手回报后，有效编辑回报数与通过率均为 0，自动条件不通过。所有分数与正文均为构造资料，不代表真实模型验收。

最终完整检查和 Windows 原生产物以 GitHub Actions 对提交的记录为准；本记录不把此前提交的构建结果当作本次修复的验证。
