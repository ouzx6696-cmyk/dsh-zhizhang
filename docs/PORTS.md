# 业务契约

本页说明操作的前提、权威变化和拒绝语义。公开 Ports 名称保留现有业务能力；工具和 HTTP 通过共同作品操作落盘，不另建一套审读、定稿或修订规则。

## 操作契约

| 操作 | 必要前提 | 实际结果 |
| --- | --- | --- |
| 创建作品 | 目标目录可以独占分配 | 初始化作品，不覆盖同名现有目录 |
| 更新根基 | 明确修改字段及范围 | 保留未传字段与作者材料；单文件原子更新 |
| 设置章纲 | 目标章可读，或确实尚未建立 | 合并章纲、保留正文，并核修订影响 |
| 暂存候选 | 目标章存在，正文非空 | 保存候选正文与元数据，当前正文不变 |
| 采纳候选 | 候选未采纳，扫描有效或可内置扫描，基线与上下文匹配 | 章节、目录、候选采纳标记及核心留痕共同可恢复 |
| 直接保存 | 实际修改在授权内；定稿正文修改须 force | 复用共同章节规则；可传 expectedRevision 防止覆盖 |
| 审读声明 | expectedRevision 是实际已读版本 | 记录主体、pass/blocked、结论与正文/上下文版本 |
| 定稿 | 当前审读通过，必要依据未变，实际前章已定稿且在授权内 | 当前版本进入 final，并登记定稿接续来源 |
| 确认修订影响 | 当前 expectedRevision | 清除本章提示，不改变正文或旧证据有效性 |
| 保存局部分析 | 指定原文、问题和实际报告，显式 save | 写工作区分析，不入公共库 |
| 应用规划 | 明确 apply，作品及所选参考基线有效 | 对应规划、标记及引用一致，不自动开写 |
| 汇编 | 被选章节可读且输出在 manuscripts 内 | Markdown 输出，不改变章节状态 |

## 版本、扫描与旁路

新候选记录目标 revision；有实际简报时绑定上下文依据。旧候选无基线需明确 current expectedRevision，或重新暂存。`force` 允许修订定稿正文，不能绕过版本冲突。

`skipBrief` 是显式简报门禁旁路，不清除候选已经记录的真实依赖。显式 append 在锁内向当前正文追加，不伪装成旧基线下的整章替换。

默认采纳会扫描未预扫的候选；已有扫描记录失效时要求重扫。strict 系列是选择性的硬策略，默认诊断不代替文学判断。内容审读与扫描凭据分开，审读主体声明也不制造作者授权。

## 返回状态与恢复

- **成功**：本次共同操作已成立，回执说明实际写入和状态。
- **拒绝**：版本、格式或授权条件不符，不能把“尝试过”表述成已应用。
- **待恢复**：部分目标可能已经写入，保留原意图；先 inspect，不重复执行新操作。

各协议解码旧格式后，只向公共恢复执行器交付已经验证的固定目标。来源、候选或输出发生冲突时停止，保留作者资产和记录。

兼容不等于补造：旧定稿不会被自动添加审读证明，旧阅读不会成为新版阅读，旧作者记录也不自动成为已核事实。文件与恢复入口见 [DATA.md](DATA.md)。
