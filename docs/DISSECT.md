# 参考分析与拆书

先区分两个目标：回答一个具体参考问题，或建立可以长期复用的正式参考资产。局部问题不需要先完成全书分析。

## 局部分析

`zhizhang_reference_analyze` 接收指定原文和问题，可准备分析简报，或核对已经完成的报告与引文。它本身不调用模型。

```json
{
  "text": "她拿出旧收据。对方核对原簿后放行。",
  "question": "材料怎样改变对方的回应？"
}
```

Agent 根据材料提出分析，再按需提交 `report`、`quotes` 和 `transfer_json`。只有 `save=true` 才保存到工作区 `analyses/ref-*.json`，不进入公共参考库，不自动启动规划。

迁移包结构为：

```json
{
  "experience": "交涉结果来自可核对的依据",
  "steps": ["给出人物能够取得的材料", "让对方实际核对后再决定"],
  "recreate": ["本书人物所求、材料来源和对方筹码"],
  "discard": ["原作人物与事件链"],
  "failWhen": "材料的证明力不足，却让对方无依据地让步"
}
```

将该对象编码后作为 `transfer_json` 字符串传入，不要求固定条数。保存结果可通过规划会话的 `reference_ids` 明确选用。

## 正式拆书入库

需要长期复用时采用下列流程，工具名省略 `zhizhang_`：

| 环节 | 产物 |
| --- | --- |
| `library_import` | 原文、来源 ID 和编码信息 |
| `library_plan` | 实际阅读范围、模式与批次 |
| `library_dissect_brief` | 本批原文及分析任务 |
| `library_facts_stage` | 逐章可核事实、结果、未知项与阅读申报 |
| `library_structure_stage` | 剧情、节奏、人物结构聚合 |
| `library_card_stage` | 尚未入正式库的技法或设计卡 |
| `library_card_accept` | 明确采纳、可复查来源的正式卡 |
| `library_report` | 按现有分析内容拼装的报告，不代替模型分析 |
| `library_combo_suggest` | 按任务建议组合，不代表必须凑齐某种卡 |

Auto 是默认分层抽样，具体范围以工具计划回执为准，不能把抽样观察写成完整全书结论。Full 先给成本与确认凭据，明确确认后才保存计划；计划范围改变需重新确认，不能默默缩减用户已明确要求的全量范围。

## 证据与阅读范围

目录扫描、已交付正文、正文已读和深读分别表达。阅读程度是申报，不因工具返回正文就自动升级。源版本变化后不能继续把旧阅读记录当作新版已读。

引号只放逐字原文；字面命中只证明材料中有这些字，不能证明解释、文学效果或市场成功。人物自述、可核事实、分析解释和待验证判断分别写清。心理或评价词只提示核对，不能误拒原作对白。

重复章号按位置区分，事实可带 `sourceStart`。无法按数字唯一定位时，完整计划会拒绝静默合并，需明确实际位置或使用指定片段分析；原文保持不变。

## 卡怎么服务原创

`craft` 卡辅助正文写法，`mind` 卡辅助作品设计。可操作、具体、不是梗概、有实际状态和明确失效条件，比字段数量更重要。参考进入规划后，重新建立本书的欲望、证据、能力边界和回应链，不能照搬原著事件。

正式入库、局部保存、规划选用是三个不同动作。正文结果也不会自动回灌成公共参考资产。阶段交接见[任务与交接](MAP.md)。
